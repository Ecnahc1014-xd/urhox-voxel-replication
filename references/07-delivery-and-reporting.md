# 证据包、清单校验、交接与管理层汇报

本文件定义**每轮迭代要归档什么、怎么校验、怎么交接、怎么向上汇报**。目标：任何一轮结论都能被外部第三方用归档文件复现，且报告不会反过来主导生产流程。

## 1. 唯一 tag

每轮可宣称“通过”的迭代必须有**一个且只有一个** tag，并以此命名全部产物。tag 必须能唯一确定：项目/对象、基线、阶段、机位集、运行序号。

```text
<project>_<object>_<stage>_<shotset>_<run_id>
```

各段定义（**本文件是 tag 方案的唯一出处**，`06` §11 只引用不重定义）：

| 段 | 含义 | 取值规则 |
|---|---|---|
| `<project>` | 项目/作品名 | 小写、无空格 |
| `<object>` | 对象或子对象名 | 小写、无空格；混合场景用“主对象+序号” |
| `<stage>` | 阶段 | **填宏观 G 编号（G0–G7）**；专项家族号（`REF-F*`/`ED-F*`/`F0`–`F5`）只能作后缀，如 `G2-ED-F3` |
| `<shotset>` | 机位集标识 | 机位清单专项文件的短名 |
| `<run_id>` | 运行序号 | 单调递增；重跑同序号视为无效 |

同一 tag 不得复用；重跑同一 tag 时必须覆盖整包并重新生成清单，禁止只替换其中几个文件（会出现“旧图配新指标”）。

机位截图命名必须严格符合 `_<SHOT_ID>_<CH>_before|after|diff.png`（`CH ∈ {A,B,C}`），否则无法被清单脚本校验。缺 `A` 组即视为**该机位无几何证据**（同 `16` §1）。

### 2.1 远程/手机审阅的打包法（实测有效）

当交付对象**只能远程查看**（手机、异地、无法操作受控机）时，散文件很难用。两件套做法：

1. **按对象打包四视角拼图**：每个对象各出一张 2×2（或 1×4）拼图，每格加标注（视角名 + 源文件名 + 源图时间），底部压一行对象名与指纹（`geometry / material / layout`）以及本项目花费行。
   - 拼图**只允许搬运已有帧**（缩放 / 粘贴 / 写字），**不得因此触发任何重新渲染**；这一条要同时写在图内（例：`no editor / no PIE / no bake / no offline render`）与报告首行。
   - 格子必须来自**互不相同的机位**，并用 md5 去重证明"不是同一视角重复"；凑不够 4 个视角就如实写"只有 N 张"，不得拿别的对象的图充数。
2. **再出一个自包含单文件**（`.html`）：把拼图与表格以 **data URI 内联**、样式内联，**零外部引用**（无 `<link>` / `<script>` / `http` 图片）；文件控制在数百 KB 量级。手机打开一个文件就能看完，不依赖同目录资源。

两条备注：

- 拼图默认取 **C 通道（成片）** 用于观感展示；**但凡拼图被用来支撑几何结论，必须改用 A 通道**，并在图内注明通道名（A/B/C），否则读者无法区分“好看”与“对”。
- 若另一条通道（如 IM 插件）可用，再推送一份；但**推送不是唯一交付**，本地必须留存。
- 拼图与单文件均属**派生件**，不入 CDN 原始件清单（见 `10` 的 I-01b）。

规则：

- **投影源不可为空**：指标 JSON 必须能追溯到一份非空、可解析的运行时投影；投影缺失时整套空间类结论作废。
- **每个机位必须有原图/改后图/差异图三件套**；只给一张“好角度”不算。
- **几何类结论只能引用 A（无光照）通道的图与指标**；外观类结论引用 B/C 通道；两者不得混用（同 `16` §1）。只用 C 通道的机位等于没有几何证据（除非按四段式登记裁剪并说明理由）。
- **光照契约与后处理快照必须每轮归档**（`lighting_contract_<tag>.json`）；它缺失时，本轮所有图像类结论降为 `PASS-WATCH`。
- **指标必须同时给均值与最差项**；只给均值视为无效。
- **每轮 9 项性能读数落在 `perf_<tag>.json`**，不能只在对话里出现；缺项写 `null` 并注明原因。
- 对象类型或尺度裁剪导致某类文件不适用时，按 SKILL.md 第 3 节的四段式登记裁剪，否则视为缺件。
- **每份产物记录大小或校验值**，避免文件被覆盖后仍引用旧指标。
- 只归档派生 JSON 不算证据；源文件、叠加图与日志必须同时在包内。
- 外部只读依赖（引擎库、第三方资产）只登记引用与校验值，不复制进包。

## 4. 临时文件 → 校验 → 原子替换

产出流程固定三步，**不允许直接原地覆盖正式产物**：

1. 写入临时路径（同目录、带 `.tmp` 后缀）；
2. 校验：非空、可解析、与上下游互相引用得上（例如指标 JSON 引用的投影文件确实存在且非空）；
3. 原子替换到正式路径，并重新生成清单。

任一步失败就保留旧产物并报告失败原因，不得留下半成品。

## 5. 清单生成

```bash
python scripts/build_evidence_manifest.py <目录或glob> [<更多输入>...] --out <manifest.json>
```

行为与退出码契约：

| 退出码 | 含义 |
|---|---|
| 0 | 成功，清单已写出 |
| 1 | 发现零字节证据文件；或加了 `--require-files` 但一个文件都没匹配到 |
| 2 | 输入非法（路径不存在、参数错误等） |

参数与行为：

- `--allow-empty <path>`：允许某文件为零字节；按**清单相对 POSIX 路径**或**绝对路径**匹配，可重复。
- `--allow-empty-name <name>`：按裸文件名白名单（会把扫描范围内所有同名文件一并放行）；**必须显式使用**，使用时会在 stderr 回显一条 `NOTE`。
- `--require-files`：即使没有任何零字节文件，只要一个文件都没匹配到也返回 1。
- `--schema`：覆盖 JSON 的 `schema` 字段（默认 `voxel-replication-evidence-manifest/v1`）。
- 纯标准库；按相对 POSIX 路径升序排序；输出含 `schema / generated_at_utc / root / inputs / file_count / total_bytes / empty_files / files[]{path,size,sha256}`；写出为 `<out>.tmp` 后原子替换，临时文件与输出本身会被排除在扫描之外。

**零字节文件必须让本轮失败**：空文件是最常见的“看着有产物其实没跑成功”的形态。

双轴与三件套的机器可校验选项（`07` §2 命名规则的可执行版）：

```bash
# 至少要有 A（无光照）与 C（成片）两个通道，且每个 before/after/diff 成组
python scripts/build_evidence_manifest.py <证据目录> --out <manifest.json> \
    --require-channel A --require-channel C --require-triplets
```

| 选项 | 作用 | 失败含义 |
|---|---|---|
| `--require-channel A --require-channel C` | 每个列出的通道至少需有一张 `*_<CH>_before.png` | 缺 A ⇒ 该机位无几何证据（同 `16` §1） |
| `--require-triplets` | 任一 `*_before.png` 必须同茎有 `_after.png` 与 `_diff.png`（反向也查） | 三件套不完整，该机位不可用于回归 |

两者失败均返 `exit 1`，与零字节同级别处理，不得忽略。

## 6. 交接必填字段

```text
本轮 tag 与基线 tag：
本轮唯一问题与结论（一句话）：
门禁状态（PASS / PASS-WATCH / BLOCKED / EXPLORATORY，逐层给）：
改动清单（文件级）+ 可回滚命令：
前后指标（同口径）与采集方式：
证据包路径 + 清单路径（含 `perf_<tag>.json` / `camera_table_<tag>.csv` / `registration_freeze.md` / `backup_<tag>.json` 四项落点）：
未关闭风险与其影响面：
下一轮建议（单一路线）：
运行时是否仍停在可查看状态：
```

交接是给**下一轮的执行者**，不是给评审看的故事；因此必须包含可粘贴的命令与路径，而不是结论形容。

## 7. 管理层一页纸

只保留五项，超出的内容一律移到参考文件或迭代记录：

1. 当前结论与是否继续投入；**结论必须分两轴陈述**：几何轴（A 通道类门禁）与外观轴（光照契约/后效类门禁）各自的通过状态；
2. 已完成的努力（资料、注册、体素、玩法、验收各自到什么程度）；
3. 不超过 3 个 P0（含影响面与解除条件）；
4. 下一步的**单一路线**；
5. 不得承诺的内容（明确写出不能保证什么）。

写作约束：

- 不写过程流水账，不写工具使用细节；
- 不用“基本完成”“接近达标”这类不可证伪表述，改写为门禁状态；
- 指标必须带口径与采集方式，禁止只给一个百分比；
- 涉及风险时必须给出“若不管会怎样”。

### 7.1 结论措辞：主张 / 依据 / 边界 三段式

任何要往外说（管理层、其他路线、外部接手）的结论，**一律写成三段，缺任一段不算结论**：

```text
主张：<一句话，可被反驳的断言；不写“差不多”“基本”>
依据：<证据等级 + 具体凭证（文件、指标、帧、API 行为）>
边界：<这句话不能外推到什么场合；什么条件下它失效>
```

配套三条：

1. **主张里不得出现未量化的程度副词**（大幅/明显/基本/差不多），要么给数字，要么改成布尔。
2. **依据必须带等级**：`本工程实测`（有留证）/ `外部文档或源码`（未在本工程跑）/ `推断`（无样本）。拿外部做法当依据时，必须写明未在本工程实测（对应 `14` §9 的分级）。
3. **边界是硬要求**：典型边界包括“仅在本发行版/本平台成立”“仅对已测尺度和对象类型成立”“未跑运行时，仅为静态关系推断”。没写边界的结论按过报处理。

反面例子（都是真实易犯的）：

| 错误写法 | 问题 | 改成 |
|---|---|---|
| “夜景光照已对齐” | 无凭证、无边界 | “主张：夜景主光方位与参考一致。依据：B 通道（后处理停用）影长比 0.42 vs 参考 0.41，本工程实测。边界：仅对该机位与冻结的 LightGroup 版本成立；换预设即失效。” |
| “比原版更先进” | 不可证伪，且混淆方法/引擎特性 | “主张：本路线在 X 上比上一轮多了一层独立重算。依据：第二条抽取路径产出 crosscheck，字段全等。边界：只证明一致性，不证明更真实。” |
| “已修复” | 无样本就下结论 | “主张：本轮无新样本 ⇒ 无法判断改善或恶化。依据：本轮未取帧。边界：不得当作已修复。”（对应 `00` 的零样本纪律） |

## 8. 报告与 Skill 的关系

报告是 Skill 的输出附件，不是生产主线：

- 详细过程、参数、脚本路径、排错经验一律回流到 Skill 参考文件或迭代记录；
- 报告结构不得反向规定工作流（例如为了凑报告章节去做无意义的重复统计）；
- 收口前确认本轮**确实写入了 Skill 增量**：不要拿目录 mtime 当证据（重新保存也满足），而是列出版本控制里的新增/修改文件，或与上一轮的 `evidence_manifest.json` 做新增项比对，并给出具体文件列表；如果本轮只产出了报告，就如实说明“Skill 未更新”，不要默认已沉淀；
- 报告不得复制 Skill 正文（避免两处判据漂移），只允许引用文件名与节号。

## 9. 本文件的通用性边界

- 目录名、文件类型与模板字段是通用形式，但**包内具体文件必须按项目实际能力裁剪**（例如项目没有运行时投影能力时，应显式记录该缺口，而不是删掉这个文件类型后仍宣称空间验收通过）。
- 清单脚本生成的是**存在性、大小与哈希**证据，不证明内容正确；内容正确性必须由第 3 节的指标与截图承担。
- 管理层一页纸的五项结构适用于生产型汇报；面向外部发布或法务合规的文档需要另加证据与授权章节。
