# 引擎操作：Lua、离线批处理、PIE 烘焙、动态体素、路径与快捷键排错（对象无关）

本文件只收录**与具体复刻对象、具体项目无关**的引擎操作事实与排错路径；引擎行为不因复刻对象是建筑、地形与水体、室内空间还是道具/载具而改变，对象相关的建模差异见 `references/03-voxel-modeling.md`。场景名、节点名、脚本名、快捷键、目录一律用占位符表示；本文不给出任何项目的真实路径、对象名或数值。

## 1. 运行模式选择与证据边界

先按任务选通道，再决定这条结论能证明什么。选错通道是“改了半天没变化”的最常见根因。

| 任务 | 通道 | 能证明 | 不能证明 |
|---|---|---|---|
| 计算投影、批处理场景、生成指标、写图片或数据 | 离线运行时 `-tool_mode` / 无头 Lua 脚本 | CPU/Scene/Image/File 层的确定性与数据正确性 | 最终屏幕渲染、光照观感、玩家视角可读性 |
| Lua 语法与引擎层校验 | `run-lua-validate` 类子命令 | 脚本可被引擎解析与加载 | 逻辑正确、场景正确、画面正确 |
| 观察渲染、场景树、角色与 PIE | 编辑器或其自动化接口 | 运行中画面与场景树状态 | 离线批处理的数值口径 |
| 创建编辑器工具 | 编辑器脚本目录下的工具脚本 | 编辑态可撤销的写入 | 运行时光标下的交互体验 |

- 前提与适用范围：以上 CLI 子命令名与开关形式来自 UrhoX 系运行时；发行版不同则名称可能不同，使用前先用帮助输出确认。
  在未确认版本上，`-tool_mode`、无头脚本执行、`run-lua-validate` 三项能力视为 **UNVERIFIED**。
- 需要画面证据时，使用确定性截图通道或编辑器 PIE，不要用离线工具“顺便”截图当作画面验收。
- 前提与适用范围：确定性截图需要固定分辨率、固定机位参数与固定时间/灯光；缺少任一项时图像差异没有意义。

## 2. 资源与脚本目录约定

- 资源路径从 **ResourceCache 根**开始书写，例如 `Textures/<name>.png`，不重复写资源根目录名。
  前提与适用范围：UrhoX 系 ResourceCache 相对路径约定；自定义挂载点时以项目配置为准。
- 用户脚本放在项目的用户脚本目录；引擎附带库目录视为**只读参考**，不修改、不打补丁。
  前提与适用范围：引擎级约定。若项目把库复制进可写目录，必须显式记录这是项目行为，不代表引擎允许改库。
- Lua 数组下标从 1 开始；输入枚举使用引擎提供的键位/鼠标常量名，而不是自定义字符串。
  前提与适用范围：Lua 5.4 语义。若项目使用不同 Lua 版本，需重新确认下标与整数除法等语义。**UNVERIFIED**：该下标约定在其它嵌入版本上是否一致。
- 编辑器脚本在顶层加载时**不得修改场景**；一切写操作在编辑态执行且必须可撤销。
  前提与适用范围：编辑器脚本生命周期约定；离线工具脚本不受此约束，但必须显式说明它不做交互渲染。

## 3. 静态体素生命周期

标准创建顺序：

```lua
-- 1 创建体积（整数原点、单位尺度）
local volume = world:CreateVolume(nx, ny, nz, <VOXEL_SIZE>, origin)
local grid = volume:GetGrid()
-- 2 写入体素（Fill / Paint / Set 等）
-- 3 最终化
world:FinalizeVolume(volume)
-- 4 标脏并重建几何
volume:MarkGeometryDirty()
volume:RebuildGeometry()
```

- 前提与适用范围：UrhoX 体素体积 API；函数名以当前版本的脚本指南为准。
- **所有创建路径必须走同一出口**。项目可以把「最终化 + 标脏 + 重建」封装成统一 finalizer；封装与否不重要，重要的是不允许存在第二条隐式写入路径。
- 缺少显式标脏/重建时，体积可能只有数据没有渲染几何；因此“写入成功”不等于“可见”。
- 体积 origin 必须是整数网格点，尺度必须是单位尺度；不要用节点非均匀缩放去修对象比例，比例不对就重建体素数据。

## 4. 动态体素与重建顺序

```lua
world:FinalizeVolumeAsDynamic(volume)
volume:MarkGeometryDirty()
volume:RebuildGeometry()
```

- 前提与适用范围：动态体积与破坏/冲量玩法相关的体素 API。
- 观察：发行版中曾出现「有物理代理、无渲染顶点」的状态，即碰撞存在但画面上看不到体素。**UNVERIFIED**：该缺陷是否已在其它发行版或更高版本修复；在每个新版本上都应先用一个可见性烟测确认。
- 因此动态体**不可省略**显式标脏与重建。
- 修改已有动态网格后按区域标脏，并调用动态代理重建入口：

```lua
world:RebuildDynamicProxy(volume)
```

- 前提与适用范围：该入口名来自当前发行版的动态体素 API。**UNVERIFIED**：入口是否在所有发行版存在、以及按区域标脏的粒度语义。
- 动态体验收要看 `solidCount`、`vertexCount`、脏标记状态与待处理网格任务队列，**不只看** `IsActive()`。

## 5. 占用登记与生成顺序

- 把每个最终实心格转成世界整数键（例如 `x|y|z`），同时登记 owner、group 与生成顺序。
  前提与适用范围：整数键方案依赖本项目 1 格 = 常量的体素契约；换尺度等级时须同步改键格式。
- 先 claim 的通常是不可动对象（地形基准面、边界、硬锚点这类；具体清单由参数表给出）；后生成体积冲突时按既定策略裁剪，并**立即标脏重建**。
- 必须输出被裁剪数量；体积被裁空视为错误，不静默继续。
  前提与适用范围：适用于所有走占用注册的生成路径；绕过注册直写网格的路径视为违规。
- **幂等重建**：同名场景根、同名烘焙节点在重建前先清除，保证重复烘焙结果一致。出现重复根节点时，画面上的“偏移”或“重影”通常不是布局问题，而是幂等失败。

## 6. PIE 烘焙顺序

交付前的标准顺序：

1. 停止旧的调试会话；
2. 打开主场景 `<SCENE_PATH>`；
3. 检查当前场景状态与脚本加载是否成功；
4. 启动 PIE；
5. 等待 baker 完成（不可只看调用返回）；
6. 检查体素/分组自检输出为 ok，且日志尾部出现完成标记（如 `done`）；
7. 检查唯一根节点、唯一 baker、投影与指标文件非空；
8. 保持 PIE/游玩画面可查看，供用户即时确认。

- 前提与适用范围：UrhoX 编辑器 PIE + baker 流程；自检标记字符串以项目实际日志为准。
- 超时保护：以 `<PIE_TIMEOUT_S>` 为上限轮询，超时即判失败并终止本轮，不要继续在未完成的状态上加细节。
- **运行中证据**：停止 PIE 可能回滚临时烘焙节点，因此停止后的场景树或截图**不能**替代运行中证据。
  前提与适用范围：编辑器 PIE 的临时节点生命周期。**UNVERIFIED**：具体发行版是否总是回滚、以及回滚范围是否包含全部烘焙产物。

## 7. 离线批处理与截图自检

### 7.1 离线 runtime 出帧：四个实测坑（2026-10-14，design-only 案；绑定发行版 0.9.0-beta.14）

用法：`UrhoXRuntime.exe main.lua -tapcode_dir=<工程> -skip_login -screenshot=<out.png> -screenshot-frame=<N> -x <W> -y <H>`（`-graphicssurfaceless` 在本发行版被忽略：缺 EGL surfaceless 支持）。

| # | 坑 | 现象 | 处置 |
|---|---|---|---|
| 1 | **不执行脚本自定义的 `Start()`** | 装配写进 `Start()` 完全不跑；无报错、截图全黑（只有顶层代码执行过） | 照 `Data/LuaScripts/04_StaticScene.lua` 顶层写法；游戏脚本放在 `<工程>/scripts/main.lua`（引擎会把该目录加入 require 路径） |
| 2 | **`.vox` 调色板差一格** | 各材质整体错位（实测屋顶被渲成墙色） | XYZI 色号 1 对应 `RGBA[0]` ⇒ material m 写到槽 `m-1` |
| 3 | **导入前预填满调色板 = 纯黑** | 把 0..255 全填成黑色后导入，体积渲成纯黑 | 槽位留给 `.vox` 导入认领；需硬度/断面色在导入后再改（本节与第 3 节同源） |
| 4 | **相机在体积内部不出画面** | 室内机位截图为黑（只剩外围少量像素） | 用“揭顶（导出时清掉天花材质）+ 外部俯视”，或改走引擎的 `*Inside` 变体 |

另两条装配纪律（与第 3/4 节同源，但离线 runtime 上更明显）：

- **单体积策略**：先写一个 `.vox` 再 `CreateVolumeFromModel`，优于逐盒 `FillBox`（上千次调用慢，且离线 runtime 对多体积共存有已知缺失）。
- **调色板/灯光**：`lightNode.direction` 直给方向（样板同法）；环境光需显式建 `Zone` 并设 `ambientSource = AMBIENT_COLOR`（默认 PREBAKED 下 `ambientColor` 是 no-op）。

> 证据边界：以上均为**单帧预览**级证据。它**不能**当作验收：无多机位、无玩法/性能读数、不做光照保真判断；写结论时必须标“单帧预览”。

- 批处理工具默认只读 + 输出到临时文件，确认非空、可解析、互相一致后再原子替换目标文件；不要直接覆盖基线。
  前提与适用范围：适用于任何生成 JSON/图片/日志的离线脚本。
- 离线工具的最低自检：输出文件存在且非空、行数或对象数与预期一致、关键字段可解析、和上一轮基线可对比。任一项不过，本轮结论作废。
- 离线通道的结论必须写成「未跑运行时 + 离线关系推断」，不得写成「运行时已正确」「画面已修复」。

## 8. 破坏与编辑操作

在运行时为 beta 的引擎上，可靠的破坏路径是**脚本级体素编辑**，而不是依赖未定型的引擎级破坏组件：

- 挖掘：固定射线 + 球形 carve；
- 爆破：较大半径 carve + 径向冲量；
- 补石：球形填充 + 明确材质；
- 碎块：继承源材质、限制数量与生命周期。

- 前提与适用范围：上述可靠性判断来自特定 beta Runtime 的观察。**UNVERIFIED**：该判断是否适用于正式发行版；在正式版上应重新做一次可见性与碰撞双烟测。
- 共享的可破坏开关容易发生状态泄漏：优先把 destructible/dynamic 之类状态作为**每次构建调用的显式参数**；若必须用临时作用域，使用异常安全的保存/恢复结构，并明确恢复默认值是“空”还是“假”。

## 9. 中文/非 ASCII 路径导致脚本加载失败时的绕行

症状：编辑器脚本报非法字节序列类错误（如 `Illegal byte sequence` / EILSEQ）。

- 前提与适用范围：编辑器脚本经系统路径读取时触发。**UNVERIFIED**：具体触发条件与是否已在后续发行版修复。
- 处置顺序：
  1. 先区分**脚本加载失败**与**游戏逻辑失败**，不要在没有澄清之前改逻辑；
  2. 复刻/烘焙优先走 PIE baker 通道，绕过出错的编辑器脚本加载路径；
  3. 如仍受阻，维护一份 **ASCII 路径镜像**：把脚本与资源复制到纯 ASCII 路径下运行；
  4. 源脚本与镜像必须做**字节级同步检查**（长度 + 校验值），并在每轮开始时复核。
- 纪律：镜像**不是新的主数据**，不得在两边各自独立编辑；对镜像的修改必须回写源侧并重新同步、重新校验。

## 10. 编辑器崩溃后的无头重开与恢复

前提与适用范围：编辑器在 PIE 或烘焙中途崩溃，且该发行版提供可用的命令行运行时或无头执行入口。以下为通用恢复顺序，**UNVERIFIED**：具体命令行参数、是否存在自动备份/崩溃恢复机制、以及无头模式对损坏场景文件的容错程度。

1. 确认残留进程与锁文件已释放，避免二次写入同一场景文件。
2. 数据完整性检查：对比场景文件与最近基线的大小与校验值；不一致时先假设被半写。
3. 用离线/无头通道做**只读探查**：统计根节点数、体积数、baker 节点数，判断场景结构是否仍自洽。
4. 结构不自洽时，从最近一个已验证基线或版本控制恢复，再重建；不在半写的场景上继续叠加。
5. 结构自洽时，用无头通道重开主场景并重跑烘焙，保留完整日志（含完成标记与分组自检）。
6. 无头重开**不能**替代编辑器的交互式画面验证：仍需一次可见的 PIE/游玩证据才能签字。
7. 崩溃记录进入本轮风险清单：写清崩溃点、复现步骤、丢失的未归档产物与恢复来源。

## 11. 快捷键与输入排错

- 快捷键**不是引擎默认值**，是项目脚本或编辑器 UI 自己绑定的。看到相同字母不要假设别的项目有相同功能。
  前提与适用范围：所有 UrhoX 工程。唯一的权威来源是项目帮助面板、主脚本、编辑器 UI 脚本与其操作指南。
- 排错顺序：
  1. 确认当前输入焦点：文本框/数字输入框获得焦点时，宿主可能暂停全局快捷键处理；先点画布或退出输入框；
  2. 确认当前模式：编辑态、PIE、游玩、飞行相机是不同模式，同一按键语义不同；
  3. 确认是否被宿主输入层吞掉符号键；必要时改用 UI 按钮，不要把失败的键盘事件当成数据问题；
  4. 确认键位常量与项目绑定一致，而不是靠记忆；
  5. 只在确认前三条无问题后，才怀疑功能本身缺失。
- 相机相关注意：不同相机的“前”不一定是世界 +Y 或同一朝向；切换相机时记录位置与朝向，避免把不同相机的截图混为同一机位。
  前提与适用范围：Y-up 左手系约定；其它坐标系需重新推导。

## 12. 日志与错误分级

| 级别 | 典型症状 | 行为 |
|---|---|---|
| 阻断 | 网格非严格、占用重叠、场景加载错误、baker 未完成、投影输出为空 | 停止交付，本轮终止 |
| 功能风险 | 碰撞未同步、碎块渲染顶点为 0 | 停止相关功能签核，其余可继续 |
| 可降级 | 非关键装饰缺失 | 记录并继续最小验证 |
| 债务 | 已分类的历史警告、过时注释 | 进入清单，不混为本轮失败 |

- 前提与适用范围：分级策略是工程约定，不是引擎行为。
- 不要用统一的错误捕获把所有错误降级成警告；必须失败的门禁在失败时必须终止本轮。
