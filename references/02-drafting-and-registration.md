# 工程制图体系与单一坐标注册

本文件规定“把参考资料转成可建模、可测量、可验收的工程图”，以及“整条流水线只允许存在一套坐标注册”的通用规则。它不绑定任何项目、对象类型或引擎；所有具体数值、名称、图号和阈值都来自项目的**参数表**（见 `SKILL.md` 第 2 节）或案例文件。缺失项一律标 `UNVERIFIED`，不得由本文件推定。图纸集的类型分派见 `references/08-subject-classes-and-scales.md`。

本文件回答一个核心问题：**坐标注册到底唯一在哪里**——给出可执行的注册链、单一变换的来源、禁止多处维护缩放的检查方法，以及“注册版本基线”后的变更流程。版本基线用于追溯/回滚，不是 AI 对几何保真推进的自锁。

## 1. 术语与占位符约定

```text
<项目>/<对象>/<子对象 A>   具体对象，由项目参数表填入，本文件不预设类型
<图号>                    图纸标识；编号规则由项目在目录层定义（见第 2 节）
<变换ID>                  注册变换的唯一标识
<基准面>                  全流程统一的高程基准（如水面、地面）
<容差>                    允许误差，必须是参数表中已声明的数值
<阈值>                    门禁通过线，必须是参数表中已声明的数值
UNVERIFIED                参数未声明或证据不足，禁止用估算值替代
```

## 2. 图纸目录与分层

工程图不是展示稿。所有复刻至少包含以下图层化的图纸目录，按“基准 → 几何 → 立面 → 语义 → 审计 → 运行时 → 来源”排序；具体图纸集按对象类型在 `references/08` 的类型表内裁剪（三种示例见第 2.1 节）。图号规则由项目定义，`<图号>` 一经分配不得改指其他语义。

```text
基准层   目录与基准说明（坐标、单位、来源、修订记录）
平面层   平面图或布置图（<子对象 A> 边界或轮廓、地坪与高程带、主要通道或空间关系、关键构件 footprint、硬锚点、净空）
剖面层   关键纵/横剖面（高程、层高或台阶、接地、通行）
立面层   关键正/侧立面或外观展开（宽高比、坡度或分段、剪影）
语义层   语义图（子对象、通道或接入、入口、稳定 ID、玩家路线与视线）
审计层   网格与占用审计图（体素网格、评分层、动态层、越界/重叠/悬空标记）
运行时层 运行时叠加验收板（参考、运行时正交投影、叠加、差异、指标摘要）
来源层   来源对照板（参考图、来源、证据等级、冲突项）
```

示例表（占位符 + 示例编号规则，具体值由项目填写）：

| 目录项 | `<图号>` 示例 | 必含内容 | 主要门禁 |
|---|---|---|---|
| 目录与基准说明 | `<前缀>-L0` | 图号、版本、坐标、单位、来源、修订记录 | 文件齐全、版本唯一 |
| 平面图 / 布置图 | `<前缀>-L1` | 边界或轮廓、地坪与高程带、主要通道、footprint、硬锚点、净空 | 平面注册、轮廓、空间关系 |
| 关键剖面 | `<前缀>-L2` | 基准面、层高或台阶、洞口、脊线、角色尺度 | 高程、接地、通行 |
| 关键立面 / 外观展开 | `<前缀>-L3` | 正/侧立面、宽高比、分段、材质带 | 剪影、体量、材质分层 |
| 语义图 | `<前缀>-L4` | 子对象、通道或接入、入口、稳定 ID、路线、视线 | 语义、净空、交接 |
| 网格与占用审计 | `<前缀>-L5` | 体素网格、评分层、动态层、异常标记 | 网格、占用、接地 |
| 运行时叠加板 | `<前缀>-L6` | 参考、运行时正交投影、叠加、差异、指标摘要 | 独立投影、视觉回归 |
| 来源对照板 | `<前缀>-L7` | 参考图、来源、证据等级、冲突项 | 可追溯、冲突已登记 |

局部对象可追加分图（如 `<前缀>-L3A`）；**禁止把透视截图冒充平面图或剖面**。

### 2.1 按对象类型的图纸集示例（至少三种）

图纸集是“同一套图层与图号规则在不同对象类型上的实例”。以下三种示例只给结构，数值、图号与深度由项目参数表确认；其余类型按 `references/08` 第 2 节的证据与注册基准类推。

| 图纸集 | 必含图纸 | 可裁剪图纸 | 注册基准（主数据） |
|---|---|---|---|
| 城市 / 聚落类 | 总平面、路网与 POI 图、关键剖面、关键地标立面、语义图、占用审计、运行时叠加、来源对照 | 无（POI 与路网为核心） | 路网与 POI 表 + 注册版本基线 |
| 单体建筑类 | 包围盒与基准图、三视图（正/侧/顶）、关键剖面、外观展开、关键尺寸链图、占用审计、运行时叠加、来源对照 | 路网、POI、岸线类图 | 包围盒 + 基准面 + 关键尺寸锚点 |
| 自然景观类 | 等高线与高程图、高程剖面、水位与岸线图、坡面与岩体分布图、植被群分布、占用审计、运行时叠加、来源对照 | 立面展开、POI、路网 | 地理配准后的等高线与水位基准 |

- 动作：混合场景按“大尺度到小尺度”把上述图纸集拼成一套，且**共用同一套注册变换与图号前缀**；不允许子对象各自维护图号或缩放。
- 动作：裁剪只裁剪图纸条目，不裁剪本文件第 7 节的静态检查项与第 4 节的注册门禁；裁剪项按 `references/08` 第 5 节的固定写法登记。

## 3. 图签与版本字段

每张图（源文件与导出文件）**至少**带以下 6 个字段；缺任一字段不得进入正式基线。项目可扩展字段，但不得删除这 6 个：

```text
drawing_id        图纸唯一号（一经分配不得改指其他语义）
revision          版本号
status            DRAFT / REVIEW / PASS / FROZEN / SUPERSEDED / VOID
 transform_id      本图消费的注册变换 ID（证明与注册版本基线同源）
author            制图/测绘责任人
updated_at        最后修改时间
```

- 状态与四态门禁的映射见 `00` §5（**本文件不自定义等价状态**）。
- `DRAFT`、`REVIEW` 不得作为正式建模基线；`FROZEN` 只用于记录注册变换与版本基线，语义强于 `PASS` 但不表示模型完成；修改必须走 §4.5 变更流程，生成新版本而不是静默覆盖；`SUPERSEDED` 只读保留，不覆盖删除。

（原先的 20 字段图签已被压到最小 6 字段：多余字段在下游无消费者，只增加维护成本。批量生产需要更多字段时，由项目参数表扩展。）

## 4. 坐标、基准面与注册链

### 4.1 坐标约定

- 坐标系与手性、单位、轴向与北向由项目参数表声明（字段名：`坐标系与手性`、`引擎默认单位`、`轴向与北向定义`），全流程只允许一套。
- 参考素材的二维坐标只能通过登记的 `reference → engine` 变换进入引擎：平移、统一或明确轴向缩放、必要时旋转。
- 二维参考的第二轴不得直接当作引擎的向上轴；平面图统一使用 `X/Z`，向上量一律记入 `Y`。

### 4.2 基准面

- 全项目只允许一个 `<基准面>`，所有高程相对它记录，禁止每张图重新定义“地面零点”。
- 剖面图必须声明剖切方向、剖切线、正向和高程基准。
- 连续测绘值与量化结果分开保存：`survey_*` 是测量值，`grid_*` 是量化结果。

### 4.3 唯一注册链（可执行定义）

坐标注册的唯一来源是一份**注册变换模块**，它是全流程唯一的变换定义者；其余环节都是消费者。注册链固定为：

```text
参考素材（参考图/测绘/来源包）
  → [注册变换模块（唯一来源，携带 <变换ID>）]
  → 主数据（按对象类型取用：POI 与路网表、边界或轮廓、等高线与水位、房型图、关键尺寸链、剖面线、机位表；见 `references/08`）
  → 生成器与布局脚本（只消费，不重定义）
  → 体素网格与烘焙产物
  → 运行时正交投影
  → 验收叠加与差异板
  → 证据包
```

注册变换模块的最小字段（缺字段视为注册未建立）：

```text
transform_id        <变换ID>，全链唯一
unit_ref           参考侧单位
unit_engine        引擎侧单位
origin_ref         参考侧原点
origin_engine      引擎侧原点
axis_map            (xr,yr) -> (x,z) 的轴向映射
scale               统一缩放或明确声明的分轴缩放
rotation            旋转（无则显式写 0）
datum_y             <基准面> 的引擎 Y 值
revision / status   revision 与 DRAFT/REVIEW/PASS/FROZEN
```

链上每一环的可执行约束：

1. 所有主数据表必须带 `transform_id` 字段，且等于当前登记的版本值。
2. 机位表、验收脚本、投影脚本必须调用同一注册入口函数，不得各自内嵌变换。
3. 运行时投影必须来自最终体素网格或场景结果；**禁止用布局脚本的同一多边形直接绘出“实际投影”自证**。
4. 变换参数变化即 `revision` 升级，并触发下游重出（见第 8 节变更影响矩阵）。

### 4.4 禁止多处维护缩放的检查方法

以下检查必须可脚本化执行，命中即标 `BLOCKED`：

1. **常量唯一性搜索**：在仓库内搜索缩放因子、偏移量、旋转常量，命中只允许出现在注册模块与其单元测试内；其余命中数必须为 0。用**命中条数**作为持久锚点，不用行号或字节数（见 `SKILL.md` §4 契约 3）。
2. **字段引用检查**：遍历所有主数据表，断言 `transform_id` 存在且唯一且等于当前版本值。
3. **往返一致性**：对每个锚点执行 `reference → engine → reference`，残差必须为 0（同一变换的逆）或落在 `<容差>` 内；超差即注册链断裂。
4. **三锚点分散检验**：至少使用三个分散硬锚点，报告变换参数、RMSE、最大误差、误差方向和异常点；只靠两点拟合不得宣称整体正确。样本缺失时结论标 `UNVERIFIED`。
5. **投影同源校验**：运行时投影的输入 hash 必须与当前基线匹配；不匹配即视为不同源，投影图作废。
6. **异常点留痕**：异常点保留原始值并开 `issue_id`，禁止在图中静默修正后“看起来对齐”。

> 以上六条是**拟合本身**的检查。另有四条检查**拟合与基准是否自证**——留出法、独立一致性、零残差警示、裁剪完整性——见 §4.6；它们同时是 `01` §7 与 `19` H5-4（区域问）的输入。

**禁止**：在参考图、主数据表、生成器中重复烘进同一缩放；用透视机位调到“差不多”替代注册；让布局脚本自证投影。

### 4.5 注册版本基线与变更流程

注册变换一旦状态为 `FROZEN`，即成为**当前版本的追溯基线**，禁止静默局部覆盖；它不禁止用户要求的新保真版本。登记：`transform_id`、`revision`、参数 hash、登记人、登记时间、对应 `baseline_tag`（登记落点为 `07` §2 的 `registration_freeze.md`）。

基线后的任何注册变更必须走完整流程，禁止“就地改一个数字”：

```text
1. 写变更单（原因、影响图号、影响数据表、本轮保持不变项、回滚点、重新签核人）
2. 按第 8 节变更影响矩阵确定必须重出的图纸与数据表
3. 生成新 baseline（禁止局部修补掩盖）
4. 重跑注册门禁 ED-F1（至少三个分散锚点）与全部受影响门禁
5. 重新四眼签核；缺失任一签核时状态最高只能是 REVIEW
6. 归档：新版本转 PASS/FROZEN，旧版本标 SUPERSEDED 只读保留；任何状态都不等于“此后不再追求更像”
```

出现注册漂移时，动作是**回退到最近一个 PASS 版本并评审**，不是继续加细节。

### 4.6 配准 / 标定防伪（四条，缺一不得升 `ORTHO_VERIFIED`）

§4.4 检查的是“变换解得对不对”，本节检查的是“这次验证**是不是自证**”。四条都必须可脚本化，读数与结论一起入档（实现：`scripts/registration_crosscheck.py`，只读）。

| # | 检查 | 判据 | 不过的处置 |
|---|---|---|---|
| 1 | **留出法** | 拟合锚点中至少 **1 个不参与**参数求解，用留出锚点报残差（`holdout[]` 入档）；`fitted_on == 全部锚点` 时只能叫“自洽” | 该标定不得升 `ORTHO_VERIFIED`；只能 `ORTHO_APPROX`（不阻止继续探索，但不得作为注册版本基线依据） |
| 2 | **独立一致性** | 同一批**对象语义点**（POI / 地标 / 物种点位，≥50 个且覆盖全域）在**第二份独立基准**上复算落点一致率，**必须同时报两组读数**（候选侧 + 对照侧），不得只报一侧；阈值 = `IdentityConsistencyMin`（**初始标定 0.80**，由 2026-09-29 负样本 62.9% / 对照 84.2% 标出，登记在项目参数表） | 候选侧不达 `IdentityConsistencyMin` 或低于对照侧的约定裕量（初始 0.10） ⇒ 该参考图不得作注册基准；已消费它的结论按 `04` §8 重采重算 |
| 3 | **零残差警示** | 拟合残差 < 0.5 px（或 < 1/5 像素量化步长）时，**自证嫌疑成立**：必须同时出示 (1)(2) 才能升 `ORTHO_VERIFIED`；“零残差”本身不算验证 | 未做 (1)(2) 而宣布“配准良好” = 违规；结论标 `ORTHO_APPROX` 并写明“未做防伪检验” |
| 4 | **裁剪完整性** | 点集覆盖率 ≥ `ClipCoverageMin`（**初始标定 0.95**）**且**越框点逐条显式声明；两者缺一即 FAIL | 覆盖率不足 ⇒ 该裁剪未覆盖对象（不得当作对象参考）；越框未声明 ⇒ 不可解释的量 |

**最小可执行算例（2026-09-29，真数据；只用公开在该批目录里的两份拟合文件）**：

| 检验 | 候选：官方 2024 裁剪（r232 拟合，7 传送点） | 对照：游戏内地图（r13 标定，7 传送点 + 2 地标） | 判定 |
|---|---|---|---|
| 拟合残差（仅拟合用点） | **0.01–0.04 px** | ~12 px（部分点为 0） | 候选侧近零 ⇒ **触发零残差警示** |
| 留出法 | 未声明 `holdout` | 未声明 `holdout` | 两侧均只能 `ORTHO_APPROX` |
| 独立一致性（1,214 官方 POI 落陆率） | **62.9%**（孔雀木 22/71、甜甜花 36/65、幽灯蕈 44/71） | **84.2%**（孔雀木 80/81、甜甜花 74/74、幽灯蕈 63/71） | 候选 **FAIL** |
| 裁剪完整性（1,214 POI 覆盖率） | 1085/1214 = **89.4%**（< 0.95）；外接框 142–706 × 157–751 vs 裁剪 560×740，越框 129 未声明 | 1204/1214 = **99.2%**（≥ 0.95）；10 个越框点（岛南缘落在截图下缘外）逐条登记 | 候选 **FAIL**；对照 PASS |

→ **结论口径**：“残差 0.02 px”与“落陆率 62.9%”同时成立时，法定结论是**未通过**（旧口径只看残差，会把这种情况判成“配准良好”）。
落陆率对“陆/水掩膜定义”敏感（同一份数据的另一套掩膜口径给出 62.4% / 88.0%）；所以第 2 条必须先**在对照基准上标定掩膜口径并记录**（哪个色相区间、是否洪填连海、是否含浅滩），再拿同一口径去判候选；换口径必须同时重报两组读数。
这两个参数（`IdentityConsistencyMin` / `ClipCoverageMin`）与裕量（`ConsistencyMargin`，初始 0.10）的唯一出处就是本节；项目的取值写入**参数表**，本文件不预设其它项目数值。
**对照侧也在“留出法”上未通过**（r13 同样没声明 `holdout`）——这说明那一项是**该批次的流程缺失**（两份标定都没做留出法），不是候选独有的错；区分候选与对照的是独立一致性与覆盖率的**实质读数**。分轮复现时不要把“对照侧也 FAIL”读成“仪器失灵”。

## 5. 图层与线型

图层与线型的命名由项目自定（本文件不规定枚举），但必须满足三条：

1. **唯一且稳定**：同一类型对象的图层名固定；禁止匿名图层，禁止同名图层承载两种语义。
2. **可被脚本按名查找**：不得依赖人工视觉识别；颜色只表达语义（阻断/观察/参考/通过/背景），不表达观感。
3. **注册相关语义不可缺**：至少要有“边界/轮廓”“高程或分层”“通道或轴线”“关键特征 footprint”“动态体”“参考叠加”“审计标记”这七类语义各一个图层，名字可自定。

（原先的 `00_FRAME`–`90_QA` 固定枚举与线型/颜色固定语义表已删除：它们在下游证据包、验收表与引擎流程里都没有消费者。）

## 6. 尺寸标注样式与容差

- 尺寸优先采用基准尺寸与分段尺寸；连续链式尺寸只用于重复构件，避免累计误差。
- 坐标标注一律写为 `X=... / Z=... / Y=...`，禁止只写屏幕像素坐标。
- 剖面线标记为类似 `A-A`、`B-B` 的方向对，箭头与视图必须互相对应。
- 引线末端必须落在明确几何或稳定 `ID` 上，不得落在阴影、纹理或模糊边界。
- 估计尺寸标 `EST`，候选标 `CANDIDATE`，未确认对象标 `LOW_CONFIDENCE`；不得用字体或颜色暗示未声明的精度。
- 每个尺寸记录来源与置信度；关键锚点用基准尺寸，重复构件用区间/模板尺寸，不得制造虚假精度。
- 容差：连续测绘值与体素整数分开记录，同一项目只允许一种量化规则（例如四舍五入或边界向外取整），规则写入目录层的基准说明。具体 `<容差>` 与 `<阈值>` 取自参数表；未声明即 `UNVERIFIED`。

## 7. 静态检查清单与门禁阶段

人工审图前必须跑静态检查；任一项失败先标 `BLOCKED`，不得用人工截图证明数据错误可忽略。

```text
文件非空、JSON/CSV 可解析、编码正确
图号/版本/状态唯一，6 个最少图签字段齐全
图层名唯一且稳定，禁止匿名图层
边界或轮廓闭合、通道或轴线定义有效（无路网/通路系统的对象以净空与通行替代项检查）、剖面端点存在
稳定 ID 不重复，坐标单位一致，source_id 可回溯
footprint 不自交，硬锚点不落在禁止净空内
同一对象在平面/剖面/立面中的高程与 footprint 一致
视图参数可解析，运行时投影输入 hash 与基线匹配
导出文件与源文件 revision 一致，manifest 列出的文件全部存在
```

门禁阶段编号固定（ED-F0～ED-F5），通过条件必须是可观测结果：

| 门禁 | 检查 | 通过条件 |
|---|---|---|
| ED-F0 文件完整性 | 图号、图签、源文件、导出、版本链 | 不缺图、不空文件、可追溯 |
| ED-F1 注册 | 原点、轴向、单位、北向、三点以上锚点 | 变换唯一，误差与来源已记录 |
| ED-F2 几何 | 边界或轮廓、高程带、通道、footprint、接地 | 平面/剖面/立面互相一致 |
| ED-F3 语义 | ID、路线、净空、低置信度、问题号 | 可交接、可定位、无歧义 |
| ED-F4 运行时 | 体素网格/PIE 独立投影、差异板 | 实际结果与图纸差异有解释 |
| ED-F5 签核 | reviewer/approver、变更记录、hash | 状态为 `PASS` 或 `FROZEN`，且当前版本基线可复现 |

## 8. 变更影响矩阵

| 变更类型 | 必须重出 | 通常不必重出 | 说明 |
|---|---|---|---|
| 原点/轴向/全局缩放/旋转 | 全部图纸、所有主数据、机位表 | 无 | 生成新 baseline，禁止局部修补掩盖 |
| 边界或轮廓/高程带/主轴 | 平面、剖面、语义、审计、运行时叠加 | 无关局部立面 | 重跑全局注册门禁 |
| 单个关键构件 footprint/高度 | 平面、相关剖面/立面/语义/运行时叠加 | 无关子区域图 | 本轮保持全局注册参数不变；需要时另建版本 |
| 通道或接入/净空/入口 | 平面、剖面、语义、受影响机位 | 无关立面 | 重做通行与视线检查 |
| 材质/线色/图签样式 | 受影响图纸导出、目录层说明 | 几何源数据 | 不得改变几何或坐标 |
| 参考来源/版本替换 | 受影响图纸与冲突表 | 无关来源图 | 必须提升 revision 并说明影响 |

变更单至少写：变更原因、受影响图号、受影响数据表、本轮保持不变项、回滚点、重新签核人、验收指标。

## 9. 四眼签核

签核采用四眼原则：制图人不能独自批准自己的图纸。签核意见必须绑定 `drawing_id + revision + issue_id`，不得只在口头或聊天中通过。

1. **制图/测绘负责人**：确认来源、注册、图层、尺寸与机器可读数据。
2. **美术/技术美术**：确认关键构件比例、剪影、语义与材质分层可落地。
3. **运行时/玩法负责人**：确认坐标、净空、接地、动态层与投影接口。
4. **QA/交付负责人**：确认门禁、证据包、版本链与可复现导出。

任一签核缺失时状态最高只能是 `REVIEW`。

## 10. 文件命名与归档

- 命名规则由项目定义，且必须包含项目、基线、图号、revision、日期等可追溯字段（示例：`<前缀>_<项目>_<基线>_<图号>_<revision>_<日期>`）。
- 同一图号必须同时保留可编辑源文件、导出图、机器可读数据源与变更记录。
- 禁止使用“最终图”“最新图”“改好版”等不可追溯名称；旧版只标 `SUPERSEDED`，不覆盖删除。
- 图纸是可视化交付层；生产依据是机器可读数据（主数据表）与源图层。字段名固定，禁止不同脚本用同义字段表达同一含义。导出（图片/PDF）不能反向作为唯一数据源。

## 10.5 输入侧接口：外部数据入图与任务书先行

本工程的图纸有两个来源：**自己测绘/绘制**，与**别人给的**（图纸、实测导出、BIM、场地底图）。
后者入图前必须过两道：

### 10.5.1 外部数据的入图前置

1. **先判形态**（矢量 / 位图 / BIM / 实测 / 场地底图），因为精度上限差一个量级；判定与可取字段见 `23` §1–§2。
2. **必须带产出契约**：源文件哈希 + 解析器与版本 + 参数 + 单位（`23` §3）。缺任一项即不得进主数据。
3. **图纸声称值 ≠ 现场实测量值**：两者差异登记为冲突（`01`），不得静默取其一。
4. **数量不当形状**：构件计数/工程量是计量口径，不得当几何证据（`23` §0 纪律 4）。

**实测导出入图的特别要求**（激光测距/自动房间扫描类）：

- **逐列保留原始列名**并写明每列含义（距离 / 倾角 / 水平与垂直角 / X Y Z / 精度），**不得猜列义**。
- **要问精度列**：没有精度列的导出不得当高等级输入。
- 近矩形房间做**方正化**、直角化（让平行墙真正平行）——这一步必须记入“处理变换”，
  因为它改变了原始数据；原导出只读保留，不得覆盖。

### 10.5.2 任务书先行 + 出图后必须评审（采纳执业工作流）

外部参考包里的执业建筑师流程有一条值得直接采纳的纪律，它把“出图”从一次性动作变成闭环：

```text
需求采集（类型/地点/面积/功能程序）
  → 先写任务书（architectural brief）——尺寸口径与取舍写在图前面
  → 再出图
  → 出图后**先给评审**（architectural critique），**暂停**，由人决定下一步
```

对应到本工程：**G2 的注册与尺寸口径先于出图**；图纸产出后必须走 G6 的投影/边缘对账与人工评审，
**不得**“出了图就算交付”；跨过评审直接进入下一轮属于流程缺陷。

## 11. 本文件的通用性边界

- 本文件只规定**方法、结构与可执行检查**，不含具体数值；一切具体值来自项目参数表或案例，缺失即 `UNVERIFIED`。
- 四眼角色名称、门禁编号 `ED-F0～ED-F5`、图层语义类别与 6 个最少图签字段都是**稳定引用名**：项目可映射岗位、追加子门禁、扩展字段，但不得改变语义、删除必需字段或改用匿名图层。
- 引擎相关约定（米制、Y-up 左手系等）以项目适配检查结论为准；换引擎先重做坐标系与手性确认，再套用本文件。
- 本文件不替代 `references/04` 的四类独立验收与运行时投影验收（注册通过 ≠ 运行时正确）；对象类型无关性——图纸分层/图层枚举/变更矩阵是结构约束，具体图纸集与图层语义映射按 `references/08` 分派。
- §4.6 的四条防伪检验是**注册侧的最低要求**；它只回答“这次标定不是自证”，不回答“模型像不像”（后者归 `04`/`06`）。它们与 `01` §7、`19` H5 共用同一份读数，不得在两处各自重算一套口径。
