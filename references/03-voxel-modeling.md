# 体素建模语法、资产分层与动态层（对象无关）

本文件只描述**与具体复刻对象无关**的体素建模方法，适用于单体建筑、自然地形与水体、室内空间、大型道具/载具、城市与聚落及其混合场景。所有地名、对象名、尺寸、层数、材质名、阈值都必须来自项目参数表或案例文件，本文件不预设任何具体数值。对象分类、证据类型与门禁裁剪以 `references/08-subject-classes-and-scales.md` 为准，本文件只给建模环节的方法。

## 0. 适用前提

- 坐标系、手性、单位、基线网格、原点定义以**项目参数表**为准；本文件不假定引擎默认值。
- 本文件的“体积”“资产”指引擎中一个可独立命名、可独立审计的体素/几何单元。
- 三条硬约束在建模阶段就必须成立，验收阶段只做核对，不做补救：整数原点、单位尺度、基底轴对齐。是否允许降级由项目参数表写明。
- 任何具体数值在本文以 `<...>` 占位符出现；未在参数表定义的一律标 UNVERIFIED，不得由建模者临时发明。

## 1. 资产描述语法：footprint + height band + semantic group

禁止用一个巨型体积同时承担足迹、细节、碰撞和动态功能。一个可维护资产的最小描述是三元组：

```text
footprint        水平投影轮廓：底面多边形或矩形（世界坐标，轴对齐或声明朝向）
height band      设计高程带：base_y / top_y（以及分段檐口、腰线、脊线的高程）
semantic group   语义分组：类别 ID + 用途（评分主体 / 识别细节 / 动态物理）
```

补充字段（建议与三元组同时登记）：

```text
体积名 name        稳定且可复现，含类别前缀与实例标识
归属 group         用于分组审计与批量重建
朝向 basis         若允许旋转，声明旋转来源与角度；否则基底轴对齐
材质/调色板 key     有限枚举，禁止逐实例随机
变体参数 variant    尺寸/材质/层数变体，见第 5 节
审计标签 audit tag  参与哪一类门禁，见 04
```

- `footprint` 是**唯一**的足迹事实来源。立面构件、腰带、檐口、烟囱都从 `footprint` 派生，不得各自重新量一遍宽度。
- `height band` 必须覆盖最高构件。若最高构件（桅杆、塔尖、烟囱、旗杆）超出 `top_y`，按第 6 节报错，不得静默裁剪。
- `semantic group` 决定该体积参与哪张检查表；语义变了要显式改标签，不允许靠命名猜测。

## 2. 三层分工：主体 / 细节 / 动态

| 层 | 职责 | 不应承担 | 典型内容 |
|---|---|---|---|
| 主体层 | footprint、接地、主要占用与碰撞 | 超界悬挑、水下桩、细碎装饰 | 墙体、体量、平台、甲板、主要屋面 |
| 细节层 | 识别度、轮廓特征、局部语义 | 改写主体评分或全局布局 | 腰线、角柱、斜撑、窗、门头、栏杆、旗、瓦口 |
| 动态层 | 物理、可移动、可破坏 | 作为静态注册参考 | 可移动载具、碎块、可破坏体、动态碰撞代理 |

规则：

1. 三层可以共享材质与语义 ID，但必须能**单独审计、单独重建**。
2. 动态层不得被当作静态注册参考；注册链只引用主体层的锚点。
3. 细节层的增减不得改变主体层的 `footprint` 与接地关系。若必须改，按主体层变更流程走全局门禁。
4. 评分/审计以层的标签为准，而不是以体积大小为准；一个很小的体积也可能属于主体层。

## 3. 建模顺序：先包围盒与接地，再构件细节

固定顺序，不要跳跃：

```text
1) 定位：世界原点 + footprint + 朝向
2) 包围盒：计算 x/y/z 全局边界，先做越界检查
3) 接地：查询实际地表顶面，确定 base_y（自然地形与水体先做基准面与高程分层）
4) 主体：拉出体量，登记占用
5) 分段：高程带与结构分段（示例：檐口/腰线/屋脊、坡面分层、甲板线）
6) 细节：识别性构件（示例：角柱、斜撑、窗、门、烟囱、栏杆、索具、陈设）
7) 动态：可动部件、碎块与代理（示例：桅杆、帆）
8) 最终化：走唯一出口登记、命名、分组、重建
```

- **先包围盒**：在写任何体素之前算出边界。任何 x/y/z 超界都报告资产名与超界坐标。
- **先接地**：在坡地、台地、岸边不使用固定底面高度；先查实际地表顶面再决定 `base_y`。
- 细节构件放在最后，因为它们数量最大、最容易被越界裁剪掩盖；各类对象的识别性构件清单见第 14 节。
- 一轮建模只处理一个类别（主体体量 / 硬锚点 / 可读语法 / 软细节 / 动态层），否则指标变化无法归因。

## 4. 可复用构件语法（构件库）

把构件集中在一处资产库，禁止在对象装配脚本里重复实现同类构件。下表以**建筑类对象**为例；其它对象类型各自的构件库按同一结构建立（见第 14 节），每类对象只允许一个构件库。

| 构件 | 参数 | 约束 |
|---|---|---|
| 墙体 wall | 起止 x/z、`base_y`、`top_y`、厚度、材质 | 厚度至少一个体素；由 footprint 派生 |
| 角柱 corner post | 角点、高度、截面、材质 | 四角对称；不吃掉墙体占用 |
| 腰线 string course | 高程、外挑（可选）、材质 | 同一对象内高程一致；变体不得逐层随机 |
| 斜撑 diagonal brace | 起止点、截面 | 坡度节奏一致；避免半格悬空 |
| 坡顶 sloped roof | 跨度、坡度、坡向、出檐 | 坡度由跨度与屋脊高度决定，不因宽度随意变化 |
| 屋脊 ridge | 走向、脊高、材质 | 走向服从建筑主轴；与坡顶共享高程带 |
| 烟囱 chimney | 位置、高度、截面 | 高度进入顶部高程带；越界报错 |
| 门头 door head | 位置、宽度、高度、材质 | 不侵占主通行净空 |
| 台阶/踏道 step | 起点、级数、单级高宽 | 单级高度受角色跨越能力约束，见参数表 |
| 栏杆/系缆桩 rail/bollard | 沿路径参数化布点 | 间距一致；不阻塞注册路线 |

- 参数化构件**优于**逐体素复制，但最终必须落到严格网格。
- 同类构件在同一对象内共享高程带与调色板；避免同一批次内出现完全一致的高程节奏（例如整条街同高平檐这类退化情形）。
- 门窗、山墙、雨棚等只是构件的组合变体，不新增构件类型。

## 5. 变量而非复制

- 用少量**显式变量**形成同批次内的对象差异：尺寸区间、高度/层数区间、材质枚举、轮廓与分段选项、开口样式（示例：建筑的尺寸/层数/山墙与门头选项）。
- 禁止复制一个完全相同的实例铺满整个批次（示例：用同一栋建筑铺满街区）；也禁止为每个实例生成专有的一次性代码。
- 随机变体必须显式传 `seed`；验收基线使用确定模式，候选模式保存 `seed` 与输出 hash。没有 `seed`、hash 和同一套门禁，不得声称存在多候选几何。
- 变量改变时，`footprint` 的派生关系必须仍然成立；不允许变量把实例挤出退界或硬锚点范围（示例：建筑的退线、通道净空）。
- 变体的取值区间本身属于参数表内容，写在项目文档，不写在本文件。

## 6. 边界与越界：必须报错，不得静默裁剪

硬规则：

1. 写入体素前计算全局边界；任一方向越界，**报错并中止该资产的最终化**，输出资产名、超界轴、超界坐标与超出量。
2. 禁止用裁剪代替修复。裁剪会制造“看似成功但缺了一角”的资产，且占用记录与视觉不一致。
3. 若确实需要超界（挑檐、桩基、桅杆），必须先把该部分拆到能容纳它的体积/层，或调整 `height band` 与 `footprint`，再重新通过检查。
4. 生成顺序造成的冲突（两个体积争同一格）必须记录被裁剪/被改写的体积名与数量；`overlap = 0` 不能作为"没有资产被裁没"的证据。记录由统一最终化出口单点写入，最小 schema：`volume_a / volume_b / cells_affected / timestamp`。
5. 越界、悬浮、下陷、不可达入口是四类独立失败，`overlap = 0` 只表示没有重复占用。

## 7. 统一最终化出口

- 所有体积必须通过**同一个**最终化封装（本项目以引擎为准，命名不限）写出：命名、分组、语义标签、占用登记、dirty 标记、几何重建都在这里完成。
- 禁止任何脚本绕过最终化直接写网格、直接改节点树或直接改占用表。
- 最终化必须幂等：同一输入重复执行得到同一体积集合与同一 hash 语义。
- 重建前先清理上一轮的生成节点，避免同名重复根节点。
- 最终化失败时保持上一版可用产物不变（原子替换），不要留下半成品状态。

## 8. 尺度层次

- **宏观层（对象整体）**：轮廓、边界、基准面与台地、主要开口与通道、识别序列。城市类对象是路网与地标排布，单体对象是主轮廓与剪影，自然景观是高程分层与岸线。对象像不像首先取决于空间拓扑与剪影，不取决于道具有多少。
- **中观层（分区/组团）**：分区边界、间距与退界、密度梯度、主轴方向、开放空间。核心识别区周围留呼吸空间，细节密度向边缘递减。
- **构件层**：第 4 节的构件库，以及各类对象自己的构件库（见第 14 节）。构件层的问题不得用宏观层的手段（挪边界、改注册）来掩盖。

层次越界是常见错误来源：构件层细节改了主体足迹、中观层布局改了注册基线，都必须按变更流程重新跑全局门禁。

## 9. 低分辨率形体表达

- 用“大轮廓 + 中层分段 + 少量高对比特征”表达地标。每个地标至少有一个远景剪影特征、一个中景结构特征、一个近景语义特征。
- 斜面用阶梯表达时保持节奏一致；坡度不因跨度或宽度不同而随意变化（示例：屋面坡度、坡面节奏）。
- 曲线用半径分段和对称检查控制：先保证中心、主轴与开口，再打磨边缘。
- 薄构件至少保留一格可见厚度，但不因“怕消失”无限加粗；用正交侧视与剪影检查决定厚度。
- 颜色块服务结构分层：按结构分件（示例：墙/木构/屋面/金属/玻璃/植被）保持有限调色板，避免逐实例随机配色造成全局视觉噪声。

## 10. 接地与支撑

- 先查实际地表顶面，再决定底面高程；在坡地或岸边不使用固定台地高度。
- 对大型地标分别审计：主体接地、外扩平台、台阶/踏道、挡土墙、支撑结构。
- 软资产（树、灌木、花坛）可有限下沉以覆盖缝隙，但下沉量必须固定并写入构件规则，不用随机偏移掩盖地形错误。
- 检测项至少包含：悬空、下沉过深、越界、不可达入口。
- 接地率口径：接地体素/底面覆盖体素/边界接触体的定义在参数表写明；口径变化必须保留旧值。

## 11. 动态层

- 动态层与主体层、细节层**分层建模**：静态支撑与可动部件必须分离（示例：船体的甲板与水下桩基分离、船体与帆/桅杆/舱盖/桅桁分离）。
- 动态体积必须能单独重建，且不参与静态注册。
- 动态体写网格后按引擎兼容路径执行“最终化为动态 → 标记几何脏 → 重建几何”；局部改动后再重建动态代理。
- 动态体必须检查：`solid count > 0`、`vertex count > 0`、几何 dirty 已清除、重建任务收敛。**有物理代理不等于有可见几何。**
- 动态物体的朝向/up 向量要在多个时间点验证，避免重心漂移后翻覆或穿地。
- 碎块回收预算与峰值必须记录并在参数表中给出上限。

## 12. 生成器接口契约（对象无关）

```text
输入：世界原点、footprint、层数/高度带、朝向、变体、语义 ID、seed（可选）
输出：主体/细节/动态体积引用、包围盒、接地点、审计标签、输出 hash
不变量：整数原点、单位尺度、轴对齐（或显式声明旋转）、稳定命名、同输入同结果
错误：越界、接地失败、占用冲突 → 报错并中止，不返回半成品
```

- 不通过非均匀 Node 缩放挤压对象；直接重建体素尺寸。
- 生成器不得在内部自行维护缩放或偏移；所有变换来自唯一注册链。
- 生成器输出必须可被第 7 节出口接管；生成器不负责最终化。

## 13. 常见失败与处置

| 症状 | 归类 | 处置 |
|---|---|---|
| 体积越界但场景看似正常 | 静默裁剪 | 改回报错并修复高度带/足迹，重建 |
| 对象底部悬空或埋入 | 接地 | 重查地表顶面，修正 base_y |
| 两体积争同一格 | 占用冲突 | 记录双方，改布局，不靠裁剪 |
| 复制铺满整批导致噪声 | 变量使用不当 | 引入显式变体变量与 seed |
| 细节体积改变了主体足迹 | 分层/层次越界 | 回滚细节，主体走全局门禁 |
| 动态体有代理看不见几何 | 动态几何重建 | 查 solid/vertex/dirty/rebuild 链 |
| 重复烘焙出现同名根节点 | 幂等 | 重建前清理生成节点 |

## 14. 各类对象的建模要点

对象类型的完整定义、证据优先、注册基准与门禁裁剪以 `references/08-subject-classes-and-scales.md` 为准；本节只给**建模环节**的摘要，回答三个问题：先做什么体量、什么不允许静默省略、验收前必须存在哪些识别性构件。具体构件名、尺寸与阈值由项目参数表填写。

四类对象共用第 1 至第 3 节的语法与顺序：先 `footprint` 与包围盒、先接地、再主体体量、最后细节与动态；下列差异只体现在“先做哪个体量”与“哪些构件承担识别度”上。

### 14.1 单体建筑

- 先做：包围盒与基准面接地，再拉出主体轮廓体量（`footprint` + `height band`），剪影确认后才做立面。
- 不可静默省略：屋顶封闭面、层高与开洞的比例关系、接地关系。挑檐、塔尖、烟囱这类超界构件必须在 `height band` 内声明并按第 6 节报错，不得裁剪。
- 验收前必须存在：至少一个远景剪影特征（屋顶形式或塔尖类轮廓）、一个中景结构特征（层带、开洞节奏、角柱类竖向构件）、一个近景语义特征（入口或材质分带）；关键尺寸锚点与包围盒一致。
- 常见失效：层高失真、屋顶走形、开洞错位；层高问题不得用非均匀缩放掩盖。

### 14.2 自然地形与水体

- 先做：基准面与高程分层（由等高线放样得到的坡面体量），再放岸线与水体；先大形态，后坡面节奏。
- 不可静默省略：坡面连续性、水位/基准高程的显式登记、水面与地形不得互相穿透。坡面断裂与阶梯化过重是失败项而不是可降级装饰；不得用随机偏移或随机下沉掩盖地形错误。
- 验收前必须存在：连续可辨的坡面（含分层高程带）、明确的岸线或水体边界、岸壁/岩体类特征（参考中存在时必须存在）；参考含植被群时，植被分布必须由规则生成而不是散点随机。
- 常见失效：水面穿地、坡面断裂、岸线不一致。

### 14.3 室内空间

- 先做：地坪与围合墙体（房间原点 + 层高 + 门洞位置），先闭合空间，再放内部陈设。
- 不可静默省略：净空（顶面到地面的可用高度）、门洞与楼梯的通过性、陈设与墙体不穿插。层高偏差必须重建体素，不得用缩放修正。
- 验收前必须存在：至少一个可达门洞或连接口、符合参数表的净空、闭合且无破口的围合边界；参考中存在固定交通构件（楼梯、坡道类）时必须存在。
- 常见失效：通道不可通过、家具穿插、层高压迫感偏差。

### 14.4 大型道具 / 载具 / 装置

- 先做：主轴线与主体量（车体/船体/机体的主要体积），先保证轴线与剪影，再做部件。
- 不可静默省略：关键部件尺寸链、重心与接地（或显式登记为悬浮/固定状态）、附属杆件（桅杆、支架、吊臂类）的越界声明；附属件不允许被静默裁剪。
- 验收前必须存在：主体剪影特征、至少一组关键部件的尺寸链关系（主桅、轮轴、推进器、铰点类）、分件材质区分（承力件与装饰件使用不同键）。
- 常见失效：部件比例失衡、附属件越界被裁、重心漂移后在动态验证中翻覆。

### 14.5 跨类型共同规则

- 每类对象只允许一个构件库；跨类型复用构件时必须显式登记来源与适用范围。
- 混合场景必须显式列出子对象及其类型，并共享同一套注册变换：第 7 节的最终化出口与第 12 节的生成器契约对全部子对象一致生效。
- 某类对象的识别性构件若未在本文件列出，先在参数表定义“最小可辨识构件”再按第 1 至第 3 节建模；未定义前不得以“细节不重要”跳过第 6 节的越界报错与第 10 节的接地审计。

## 后裁定细则（与正文冲突时以本节为准）

1. **薄构件厚度（可判定）**：厚度 ≥ 1 体素；判定方式 = 正交侧视剪影比对（该构件必须在剪影中可见，且投影覆盖体素数 ≥ 参数表“最小可辨识构件”所对应的体素数）；判定人、截图与结论写入 `iteration_<tag>.md`。不达标时：加厚到满足，或按 SKILL.md 第 3 节登记降级并将本轮状态降为 `PASS-WATCH`；禁止“怕消失就无限加粗”。
2. **实例复制的计数上限**：同一批次内“参数元组完全相同”的实例占比 ≤ `<T_DuplicateRatio>`，且每类构件至少 `<N_VariantGroups>` 组参数变体（两个符号已在 `04` §0 登记）；采集方式 = 按构件参数 hash 分组统计，结果写入 `audit.log`。超出时拆变体或改用参数化生成，不得整批复制。
3. **构件库容器（可审计）**：构件库固定为单一目录（默认 `assets/<object>/Prefabs/`，项目可覆盖并在参数表登记），并带 `parts_index.json` 登记每个构件的 `id / 来源 / 适用范围`；跨类型复用时必须在 index 里登记来源与适用范围，否则视为未复用（禁止隐式共享）。

## 本文件的通用性边界

- 本文件只给方法、顺序与约束，不含任何具体对象或城市的尺度、层数、材质、阈值或路径；所有数值以占位符出现，须由项目参数表填入。
- 第 4 节的构件清单与第 14 节的各类对象要点是**语法建议与方法摘要**，不是引擎 API，也不含实测数值；具体实现方式、命名与调用链以项目与引擎文档为准，未验证项标 UNVERIFIED。
- 第 6 与第 7 节属于工程契约，跨引擎复用时需要先确认该引擎是否提供等价的越界检查与统一最终化出口；若无，必须先补齐等价机制再套用结论。
- 本文件不规定验收阈值，也不替代 04 的四类检查表；建模通过不等于验收通过。
- 换引擎或换坐标系时，本文件的顺序与分层仍然成立，但所有“以参数表为准”的条目必须重新填写与复核。
