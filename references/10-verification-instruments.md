# 验收仪器册（把"命令成功"变成"证据成立"）

本册收录**与复刻对象无关**的验收仪器：它们不判断"像不像"（那是 `04`/`06` 的事），只判断"**这次的产物是不是真的**"。

## 0 为什么需要这一册

UrhoX / 体素链路里有一整类**静默失败**：命令返回成功、文件正常落盘、指标看着绿灯，而东西根本没做出来。本轮实测到的四种：

| 静默失败 | 表面现象 | 真实后果 |
|---|---|---|
| 越界写入被静默丢弃 | `FillBox` 无报错 | 幽灵格：占用表有、栅格没有；`solid_cells` 虚高 |
| 材质/重绘未落盘 | 命令成功 | 两轮"指纹相同"被误读成"零改动" |
| 渲染未发生 | 截图**同样是 8819343 字节** | 空帧被当成证据留存 |
| 日志被并发任务抢用 | 解析成功 | 审计张冠李戴（甚至读到别的对象的体积名） |

**共同结论：任何仪器都必须有负样本。** "我实现了检查"不等于"检查能拦住"——见 I-04 的代际盲区链，三条规则分别被三个不同的负样本逼出来。

## I-01 占用对账恒等式

```
sum(每体积 GetSolidCount()) == 占用表 cells 计数
```

- 输入：每个体积的引擎栅格实物数（`grid:GetSolidCount()`）+ 自建占用表的条目数。
- 输出：两者相等 / 不等（不等即存在幽灵格或体积互叠）。
- 为什么有效：左边来自**引擎自己的栅格**，右边来自**你的声明表**；两边独立计数，任何一侧撒谎都会破。
- 本次战果：拓出 R2 的 144 格幽灵格、R1 的 32 格幽灵格（旧 audit `solid_cells=308132` vs `sum=308100`）。
- 边界：只能在"同一次构建"内比；跨轮比没有意义。

## I-01b 完整性门禁（清单 + 拒写 + 空输入陷阱）

- 工序与现场事故（三个模式怎么跑、三方对比怎么失败）见 `references/11` §3.5；本节只负责**仪器行为与失败模式的命名**。

- 仪器：给证据/参考包维护一份**可验证清单**（逐条 path / url / source / bytes / md5），并提供三个模式：默认（缺则取、不缺则跳、**不符则拒写**）、采集基线（`--init-md5`，不联网）、**`--verify`（只读重拉，逐条报告"是否仍能产出记录中的字节"）**。
- 反向测试（必须做）：在沙箱里把一个文件改成与清单不同的字节，验证**脚本拒写且文件未被改动**（exit 非 0）。每道门禁都要有一个它能拦住的负样本。
- **原始字节哈希对 HTML 页面不稳定**：实测 10 张图 `--verify` 100% 字节一致，而两个 wiki 页面 raw md5 全不一致（页面含时间戳/广告位/nonce）。页面应改用**规范化内容哈希**（例如把页面投影成域结构串）。
- **空输入哈希 = 永久假绿灯**：当规范化输入合法地可为空时，哈希恒等于空串 md5（`d41d8cd9`），于是永远通过。**任何校验都要先断言输入非空且非退化**；输入为空时该条目必须标为 `not-applicable` 并**不计入通过数**。

## I-01c 审计再生（可一键重算）

- 仪器：一个**只读**脚本，按 tag 重跑产物抽取并复算 `solid / 三指纹 / 接地率 / 对账`，与该轮归档的审计 JSON 逐字段比对。
- 为什么必须有：没有再生器时，案例里的“断言 ↔ 复核”只能退化成“回查某个 JSON”，读者**无法自证**；而归档审计是引擎侧 kit 产出的，跨引擎版本、跨工具修订都不保证可复现。
- 实测不对称（2026-09-23 工具巡检）：R3 有审计再生器（带 `--tag` 与错锚点反向测试），R1/R2 **没有** ⇒ R1/R2 的案例 0D 只能写“回查留证件”。
- 纪律：**审计再生脚本应与取帧脚本同批建**（同 `tools/`、同 ASCII 路径纪律、同 `--tag` 语义），并在案例的 `0D 断言↔复核` 里被引用；被引用的脚本必须真实存在——`case_index.py --check` 的 TOOLS 门禁会逐个校验。

## I-02 越界闸（拒写 + 拒 claim）与写类型诊断
- 仪器：在**所有**写入路径（`box` / `carve` / `paint` / `set` / 米制代理）前置边界检查；越界即**拒写且拒登记**，计入 `out_of_bounds_writes`，并让总自检直接判失败。
- 关键纪律：**拒写必须同时拒 claim**。只拒写不拒 claim 就是幽灵格的生成器。
- **修法取决于写入类型，不要一律"放大声明"**：

| 闸报类型 | 真实病类 | 正确修法 |
|---|---|---|
| `box`/`carve`/`set` 越界 | 几何真的伸到声明外 | 改体积声明（或收几何） |
| `paint` 越界 | **目标层/位置不存在**（典型：把层中心当盒子下沿） | **改目标坐标**；放大声明只会把闸刷绿而东西仍不可见 |

- 本次战果：R2 的舷缘铆钉——修前 top_plan 铆钉色像素 **0**，改对目标层后 **3685**；若按"放大 `ny`"修，闸会变绿而铆钉继续画在不存在的那层上。
- 边界：拒写粒度是**整盒**，所以部分越界的盒子连界内那部分也会丢；`out_of_bounds_writes ≠ 0` 时 `solid_cells` 会低于应得值。
- 自检器必须覆盖 fill / paint / carve / set **四条**路径（R2 的检查器最初只覆盖 fill，因此没能先拓出 paint 越界）。

## I-03 变化检测的四类信号与仲裁规则

| 信号 | 覆盖 | 性质 |
|---|---|---|
| 声明的几何指纹 | `claim` 收到的盒子范围（fill/carve） | **声明**变了才会动；**不是实际格集** |
| 材质指纹 | 显式 paint + box 自带 paint | 材质变了会动 |
| 布局指纹 | 体积声明（名/尺寸/格点原点）+ 越界拒写次数 | 改尺寸/改声明会动 |
| `stats`（fills/carves/paint/box_paints） | 操作计数 | 能定位变化类型 |
| 帧 md5 / luma / 逐区域像素差 | 实际渲染结果 | **唯一仲裁者** |

三条硬规则：

1. **哈希与 stats 只是变化探测器；逐像素比较是唯一仲裁者。** "四项中有一项变了" ≠ "内容变了"。
2. **两个方向都会错**：几何指纹会**漏报**（纯材质重绘它不动）；材质/计数指纹会**误报**（跨工具修订边界不可比——实测逐像素只有 1 LSB 差异而材质指纹全变）。
3. **工具一改就重立基线**：修改共享构建工具后，旧的材质指纹与 `stats` 一律标"不可比作废"，以新修订下的首次运行为新基线。

## I-04 帧内容门禁与"负样本代际链"

截图尺寸与字节数恒定（实测 2040×1080 / 8819343 B），**文件大小永远不能判空帧**。

现行判据（五条同时成立才 PASS）：

| 信号 | 阈值 | 空帧实测 | 正常帧实测 |
|---|---|---:|---:|
| `uniq_colors`（512 宽降采样） | ≥ 1000 | 43 | 11467 |
| `luma_mean` | ≥ 3.0 | 8.01 | 135 |
| `luma_std` | ≥ 5.0 | **0.58** | 33~65 |
| `content_ratio`（远离本帧中位背景 >40 亮度的像素占比） | ≥ 1% | 0.01% | 18.31% |
| `near_black_ratio`（**全分辨率** luma<8 占比） | ≤ 90% | — | ~0.4% |

**代际盲区链（必须保留，跑 `--self-test` 会直接打印）：**

```
synthetic black          black=100.0%   v1 拦住
real engine empty        black= 0.00%   v1 放过、v2 拦住
synthetic black+island   black=91.21%   v1 放过、v2 放过、v3 才拦住
```

- v1（`uniq≥16` + `luma≥3.0`）对真实空帧无效：真实空帧**不是纯黑**，是一层极淡暗角渐变。
- 只凭 `uniq/std/content` 会被"91% 纯黑 + 一小块亮岛"骗过（亮岛让画面"显得很富"）。
- **硬规则：每条新阈值规则必须附一个“它能拦住、而上一代没拦住”的负样本，否则不得写入阈值表。**
- **负样本要覆盖不同的失效方向**（两个样本在相反方向各拦一类，加起来才封住）：

| 负样本 | 特征 | 谁来拦 |
|---|---|---|
| 真实引擎空帧 | `uniq=43 / luma_std=0.58 / content=0.01%`（**无结构、几乎无对比**） | v2 的 `luma_std` + `content_ratio` |
| 合成“91% 黑 + 一小块亮岛” | `uniq=6459 / luma_std=38.22 / content=8.88% / black=91.21%`（**暗区占比过大但局部颜色与结构都正常**） | **只有** v3 的 `near_black_ratio` |
| 纯黑帧 | `uniq=1 / luma=0` | v1 就能拦（拿它做自检**等于没验**） |

单看 `uniq/luma/std/content` 两个方向都看不出来，所以只做一个负样本必然留一个盲区。
- **负样本必须来自真实失效模式，不能是方便造的合成样本**：用合成纯黑帧自检会"通过"，而闸门实际失效。

## I-05 共享运行目录的日志隔离（标签 + 运行绑定）

> 同源命名陷阱的**另一种后果**——烘焙节点与体积根同名会把节点自己删掉——见 `references/12-channel-divergence.md` §1.1。

> **命名与审计归属的耦合陷阱**（R3 实测，2026-09-22）：审计行与日志标签用的是**体积根名**（`subject.NAME`），不是 baker 节点名。若把 PIE baker 节点的名字传给 `rootName`（或把体积根改成 `<Name>Baker`），**审计归属会立即与标签失配**——所以“baker 节点不能与体积根同名”这条修正要连带确认两件事：① 场景 xml 里的 baker 节点名与体积根名不同；② `BuildSubject` 不传 `rootName`（或传的值仍等于 `subject.NAME`）。四个必须对齐的载体：场景 xml 节点名 + 其 `LuaScriptInstance` 脚本、`project_info.json` 的 `node`、`bake_editor.py` 的 `BAKER_NODE = INFO["node"]`、`subject.NAME`。

多任务并发共用同一个引擎 `logs/lua/` 目录时，审计数据靠日志行回传，因此必须做**三层绑定**（少任何一层都会留一个静默通道）：

1. **subject 标签**：只接受带 `[<自己的 subject>]` 的行——否则会读到别的对象（实测读到过别人的体积名）。
2. **运行绑定**：标签只证明"是我们的"，**不证明"是本次运行的"**。取到的行必须**晚于本次运行起始时间**，判据用**日志行自带的时间戳字段**（如 `payload.t`），**不要只用文件 mtime**——mtime 只说明"这个文件被写过"，行时间戳才能说明"这一行是本次跑出来的"。找不到本次审计就**响亮报警并拒绝写审计**，而不是回退到旧行。
3. **锚点体积 + 自身 subject 双校验**：从新到旧扫日志，只接受 `volumes[].name` 含**本对象独有锚点体积名**、且 `payload.subject == <自己的 subject>` 的行；找不到就 `exit 2` 且**一个字节都不写**（不许"退回到全部日志"）。这层堵的是"标签对、但对象已经不是这个对象"。

**双路径互校**：主路径（标签 + 运行绑定）与第二路径（锚点 + subject）应各自产出独立审计文件（`shots/<tag>_audit.json` 与 `shots/<tag>_crosscheck_audit.json`），要求**字段与体积名单全等**。

**反向测试必须真跑**（不能只写在注释里），两种错法都要验：

| 反向用例 | 期望 |
|---|---|
| 正确标签 + 错锚点（`NoSuchVolumeName`） | `exit≠0`、**不产生任何产物**、打印候选行数与不达标原因 |
| 正确锚点 + 错 subject | 同上 |

理由："静默回退到旧审计"这类洞**只有反向测试才会暴露**——正向跑通一次不能证明闸有效。

- 失败模式：变体模块改名 / 进程崩在审计前 / 探针模式 ⇒ 标签缺失 ⇒ 静默退回上一次同 subject 的审计，造成"帧是新的、审计是旧的"。
- 附带纪律：截图与审计都要落到**纯 ASCII 路径**（引擎的文件 API 打不开非 ASCII 路径），再拷回工程目录；审计 JSON 只在三层都通过后才落盘，落盘路径进 `shots/evidence/<tag>_*` 快照。

## I-06 引擎外独立重算验相

- 仪器：在引擎之外（普通脚本）重算每个体积的格集，检查两两不相交、union 计数、逐体积与引擎一致。
- 为什么需要：引擎报 `overlap_cells=0` 只证明"**它算的**没有重叠"。独立重算才能证明"**几何**没有重叠"，两者互为交叉验证。
- 本次战果：8 个体积两两不相交、逐体积 8/8 与引擎一致；同时把检查器从"只查占用"扩到"全部写入路径"后，复现出与引擎闸一致的 12 处越界。
- 边界：只能验**声明与栅格的一致性**，不能替代表面/材质/渲染验收。

**两种落地形态（实测）**：

| 形态 | 做什么 | 实例 |
|---|---|---|
| 几何不相交重算 | 引擎外重建每个体积的格集，算 `union` 与各体积 `owned`，必须 `union == owned` 且逐体积与引擎一致 | 8 体积：`union = owned = 39468`，逐体积 **8/8** 一致 |
| 第二条抽取路径 | 用与主路径**不同的判据**再抽一次审计（如锚点体积 + subject 双校验），与主路径做字段级全等比对 | `r4_audit.json` 与 `r4_crosscheck_audit.json`：`subject / volume_count / volume_nodes / solid_cells / overlap / non_strict / floating / ground_rate / fingerprint` **全同** |

**必须同时看的对账恒等式**（与 I-01 配套）：

```
sum(每个体积的 solid 数) == 占用表 solid_cells
```

若只看 `out_of_bounds_writes == 0`，会漏掉"历史遗留幽灵格"这一类：实测归档的 8 份修复前审计里 `phantom` **恒为 108**（跨四组几何、三个阶段都在），而两个探针轮是 `phantom=0 / oob=33` —— **两道闸测的不是同一件事，两个都要**。

## I-07 参考量测：沿中轴取连通段宽度

- 问题：参考截图里相邻屋顶会"合并"成一个连通域，导致靠轮廓分割量出的宽度被**满窗截断**。
- 仪器：沿被摄对象的**中轴**做扫描线，按颜色分段取连通段宽度；配合极点/椭圆拟合校验外轮廓。
- 输出：以"对象外轮廓尺寸 D"为分母的**无量纲比值**（例如檐口宽/D、井口/D），这样不同截图尺度可比。
- 失败模式：把"某条色带的内沿"误读成"某个台阶"。**必须先确认线段落在真实台阶上**，否则读数是假的（实测：一条 0.51 的读法其实落在色带内部，被自己的连通域+极点复核推翻）。
- 纪律：**先用能全盘看到对象的帧定标，再用多帧交叉校验**；若参考包里没有第二张全盘可见图，就登记"无法交叉标定"而不是硬凑。

**四条判据（全部满足才叫"无歧义读数行"）**：

1. **strict**：不贴扫描窗两边（否则是截断下界）+ ±3 行内是宽度极大 + 下方 8 行内收窄 ≥5%（站在"尖端"上而不是暗块内部）。
2. **保守阈值复核**：同一连通段在保守阈值（实测 `70`）下必须保住 ≥80% 宽度——用来剔掉"只比背景暗一点"的亮物。
3. **归属**：读数必须属于**同一个对象**的竖向序列；归属不成立时，即使宽度有效也不能进比值。
4. `runs`（该行有几段互不相连的暗区）**只作诊断，不作否决**：同行邻栋会造成 `runs>1`，但"含中轴的那一段"仍可能是有效读数。

**可用性判定（硬门槛）**：`measurable = (无歧义读数行数 ≥ 2)`。不足 2 条时，正确产出是"**不可测**"四个字，不是折中数、不是"将就用一条"。

**方法自检（把"方法没问题"变成可复算的数字）**：用自己的**正交渲染帧**当控制组——渲染侧的真值写在代码里（已知尺寸 + 已知行号），用**同一套过滤器**跑一遍，报最大误差。实测 4 条真值行最大误差 **0.15%**。

> 结论句式固定为：**"方法自检误差 X%；参考侧 N 条无歧义行 ⇒ 这是证据限制，不是方法失效。"** 没有这条自检，就不能说"量不出来是参考的问题"。

**五类实测失败模式**（每条都有留证件）：

| 代号 | 失败模式 | 识别方法 |
|---|---|---|
| A | 阈值把**前景遮挡物**算成对象（实测：花冠亮度 91.5 < 阈值 110） | 打印轴像素 RGB/luma；保守阈值下簇消失即遮挡物 |
| B | 把**屋脊/顶部碎片**读成檐口行 | strict 过滤直接否掉 |
| C | **轴不是对象的轴**（选了画面中心 → 量到配殿/树影） | 把轴像素颜色与对象材质比对 |
| D | 候选只剩 1 条却仍写进文档 | `measurable = tips ≥ 2` |
| E | **旧读数不撤回、继续驱动几何** | 撤回要**两处同时做**：文档结论 + 代码注释里的归因 |

**适用边界**：只适用于能整体看到对象的帧；只给**无量纲比值**、不给绝对尺度（跨图比例误差量级 ±15%）；不同光照的同一对象读数不可混用；它只证明"某个水平特征有多宽"，**不证明该特征是什么**（檐口/女墙/屋脊的语义判断必须由人看叠图给出并登记）。

## I-08 证据保留：一轮一 tag + 快照

- 问题：截图工具用同一个 `--tag` 重复跑会**覆盖**上一轮同名产物（实测：三代几何的终版帧已无法回溯）。
- 约定：**一轮一个 tag**（`r1`/`r2`/…），`final` 只允许用一次；每轮定稿把拼图 + 审计 + 索引**快照**到 `shots/evidence/<tag>_*`，散图保持原名。
- 报告里引用哪个 tag，就自带哪个 tag 的快照路径。

## I-09 体积声明纪律

**每个体积的声明尺寸（`nx/ny/nz`）必须包住它自己的每一次写入。** 声明比几何小 ⇒ 静默截断 + 幽灵格。诊断与修法见 I-02 的写类型表。

## I-11 参考同一性与对象在场性（H5 / H6 的执行器）

- **判据的唯一出处是 `19` §1（H5：对象 × 区域 × 版本；H6：图上必须有对象本体）与 §1.2（声明字段与机器判据）**；本册只登记仪器行为、失败模式与负样本，不重写条款。
- 实现：`scripts/ref_identity_gate.py`（读 `identity_declarations.json`；逐图 PASS / FAIL / UNKNOWN；只读，不写参考包；exit 0/1/2）。
- 为什么需要：见 `19` §1 的理由段。它挡的**不是画质**，而是“这张图是谁、里面有没有它”。
- 反向测试（必须真跑，不能只写在注释里）：

| 负样本 | 特征 | 期望 |
|---|---|---|
| 错区图（区域问对不上） | 候选落点一致率 62.9% vs 对照 84.2%；外接框越裁剪 129/1214 | **FAIL**（H5-4） |
| 自造图占“参考”位 | 拿不出外部同一性证据（**读数**，不单独设闸） | **FAIL**（H5-2 / H5-5；理由 = 无外部证据，不是“因为它是自造图”） |
| 不含本体的帧当比例锚 | `usage=anchor` 而 `present` 未声明 | **FAIL**（H6-1） |
| 含本体的外部帧（对照组） | `present=true` + 签核 bbox + 母图 | **PASS**（不得“一律 FAIL”） |

- **升级边界（按 2026-09-29 的缺陷复发矩阵裁定）**：**自造图禁入**与**来源语义去重**属 **单批 P2**，不得单独升级为可拦人门禁，只落 `01` 动作 + 本仪器读数；它们在本册里出现的 FAIL 都是**别的门禁的失败例**（自造图过不了 H5 是因为没有外部证据；同图多用撤的是证据计数）。

- **边界（最重要的一条）**：脚本**不能判语义真伪**。它只能保证“三问问过、证据可解析、独立一致性读数达标、在场性有人签核”。把未签核的 `present` 当已核实 = 伪造通过（与 I-01b 的“空输入哈希 = 永久假绿”同类）。
- 与其他仪器的关系：区域问的读数由 `02` §4.6 的独立一致性检验提供（`scripts/registration_crosscheck.py`）；等级判定仍归 `01` §3.2。

## I-12 形制 / 形态检查（垂直维不被“非空帧”骗过，也不被“方法合格”骗过）

- 问题：帧内容门禁（I-04）只问“这帧是不是空的”，不问“这帧里的东西像不像”。实测（2026-09-29）：一个“海边平地 + 约 210 m 台面”的双峰台阶地形，8 个机位 **8/8 PASS**——因为每一帧都富含颜色与结构。
- **另一个陷阱（已更正口径，写在这里防误用）**：“台地”本身不是错——世界实测点最低 151.4 m，高原台地**可能是对的**；错的是**没有任何独立证据能判它对错**（形态参照缺失），而门禁从不问这个问题。所以本仪器的结论名是 **`TERRACE-UNPROVEN`**（形态未经独立证据校验），不是“台地=坏”。
- 输入：高度场（如 `heightmap_*.npz` 的 `height_m/land`）或逐体素占用的顶部高程；**必须**带 `field_kind ∈ {terrain, roof_top, unknown}`；建议同时给 `--height-source` 与 `--survey-min`（实测点集的最低高程，用来看“哪些格子根本没有实测支撑”），字段定义见 `04` §3.1。
- 实现（互补两件，缺一不可）：
  - `scripts/heightfield_form_check.py`：只产读数，不拦人；exit 0 正常 / 1 命中 `TERRACE-UNPROVEN` / 2 用法错。
  - `scripts/form_shape_check.py`：**复核件**——高度 provenance 分层（`PROVENANCE-UNRESOLVED`）、剪影长宽比/转折点（`SILHOUETTE-MISMATCH`）、与读数交叉复核；`--self-test` 内置 r17（色带证伪）与 r18（留出验证）两条**正样本**，自检不过 ⇒ 本件不得用于验收（exit 3）。
- 输出（读数，不是门禁）：

| 指标 | 定义 | 实测（03 鹤观 `heightmap_vox.npz`） | 真地形对照（Rushmore DEM b5/g070，561×681 @1 m） |
|---|---|---:|---:|
| 单一高程带占比 `band_share` | 落在 p05–p95 范围 1/20 宽的最满一箱的占比 | **0.305** | 0.106 |
| 最满 1 米带占比 `flat_share_1m` | 落在最满 1 m 值域内的格数占比（层厚集中的指纹） | **0.208**（最满带 = 2 m） | 0.018（最满带 = 81 m） |
| 无实测支撑占比 `below_survey_min` | 低于实测点集最低高程的陆地占比（只在给了 `--survey-min` 时输出） | **0.420**（实测最低 151.4 m；其中 ≤25 m 占 37.9%） | 0（对照未给该参数时不输出） |
| 形态判定 | `band_share ≥ 0.25` 或 `flat_share_1m ≥ 0.10` → `TERRACE-UNPROVEN` | 命中 | 未命中 |
| （诊断）`spike_ratio` | 最高 1 m 箱计数 / 非空 1 m 箱计数中位数 | 746 | 5.0 |

- **适用边界（不写进声明就会误伤）**：本检查只对 `field_kind == terrain` 生效。屋顶高程（城市 / 建筑类）**天然聚类**——同一口径下某平地城市屋顶场 `flat_share_1m = 0.113 / band_share = 0.271`，会误报；城市类必须改用**地面高程**并声明 `field_kind=terrain`。
- 无剪影参考时的处置：`TERRACE-UNPROVEN` 不是“模型错”，是**证据缺口**：不得据此声称“垂直维已校验”，`04` 表 C 的 C2 记 `UNKNOWN`（不得记 PASS），下一轮补 ①同轴实机透视 / 剪影参考 或 ②官方 DEM / 剖面。
- 反向测试：03 的 `heightmap_vox.npz` 必须报 `TERRACE-UNPROVEN`；Rushmore 的 DEM 必须不报（两条都留证）。
- 剪影半边（有参考时）：正 / 侧剪影的长宽比、主要转折点（峰 / 台 / 檐）相对位置；口径与阈值沿用 `04` C2 与 `19` §3.1 的边缘一致度，本仪器**不另立阈值**。

## 通用性边界

本册只描述**验收仪器的行为与失败模式**，不含任何具体项目名、路径、阈值常量（数值均以"实测值"形式给出，换项目必须重测）。仪器实现随引擎版本变化，换发行版或大版本后必须重新确认：边界检查是否仍然必要（引擎是否已修静默丢弃）、截图尺寸/字节常量是否仍恒定、日志字段名与时间戳格式是否一致。
