# 光照与后处理的保真：对照分析的第二根轴

`14-cross-engine-methodology.md` 的第 4 节给出的五级刻度（集合 → 几何 → 投影 → 感知 → 语义）是**几何轴**。它管不住"像不像"的另一半：**光照与后期**。本文件补第二根轴。

## 0. 两条铁律

1. **几何结论只能在"无光照通道"上取。** 一旦画面里进了光照、雾、bloom、tonemap，像素差异就不再只归因于几何。
2. **外观结论只能在"光照契约冻结 + 后处理停用"的通道上取**，且**光照契约不得由脚本事后拼凑**——它是一份要版本化的主数据。

违反任一条得到的结论，无论多么"看起来对"，都不得写进验收。

## 1. 三通道纪律（本文件的核心）

| 通道 | 怎么配 | 能证明什么 | **不能**证明什么 |
|---|---|---|---|
| **A 无光照/平色** | 用引擎自带的 unlit technique 或"只输出 albedo"的自定义材质：`NoTextureUnlit.xml`、`NoTextureVCol.xml`、`DiffUnlit.xml` | 剪影、比例、轮廓特征、材质槽分布、几何一致性 | 任何光照、阴影、氛围 |
| **B 光照契约** | 冻结的 LightGroup 预设 + 明确光源清单，**后处理全部停用** | 光照方向/强度/色温、阴影、明暗交界、材质响应、雾 | "最终观感"（还缺后期） |
| **C 成片** | 交付时的真实 RenderPath（后期全开） | 最终观感、氛围、可展示性 | **几何正确性、光照正确性** |

使用规则：

- ③投影级指标（剪影 IoU、包围盒、质心、特征点）**只在 A 通道采**。
- 光照归因**只在 B 通道做**。
- C 通道只用于展示与主观评级；`04` 表 C 的 C9（透视近景语义）本来也只作排优先级用。

> 工程后果：每个机位要出**至少 A 与 C 两组**（需要归因时再加 B）。只有一组 C，等于没有几何证据。

## 2. 光照契约：必须冻结的清单

| 项 | 说明 |
|---|---|
| LightGroup 主数据 | 预设名 + 版本 + 文件哈希（**不是**"用的是白天"这种口语） |
| Zone 归属与 priority | 谁在生效；是否另建了 Zone |
| 主光 | 方向、色温或颜色、亮度、是否物理单位、阴影开关与分辨率/bias/级联/焦点 |
| 附加光 | 点光/追光/面光的完整清单（位置、朝向、半径、内外锥角、ramp/shape 贴图） |
| 环境光 | ambient 来源模式 + SH/IBL 来源 |
| 大气 | 深度雾、高度雾、体积雾（密度/高度/衰减/可视距离/相位 G） |
| 后处理 | 见第 6 节的开关清单 |
| RenderPath | 资源名 + 版本 |

**四个已实测的陷阱**（不写进契约就会踩）：

1. **LightGroup 自带 Zone（priority = -1），再建一个 Zone（默认 priority = 0）会静默接管并丢掉整个预设**（IBL、SH、Bloom、雾）。"光照莫名其妙变了"的第一嫌疑。
2. **默认环境模式下 `zone.ambientColor` 是 no-op**：引擎硬下发 `cAmbientColor = (0,0,0,0)`，环境光由 SH 驱动。要改环境光只能换 LightGroup 预设，或走运行时环境光烘焙（`AMBIENT_SKYBOX` / `sourceTexture` / `AMBIENT_COLOR`）。
3. **SH 球谐、环境贴图 cubemap、环境贴图角度没有暴露给 Lua** ⇒ 想换大气就得换预设文件。这正是"光照必须是主数据"的原因。
4. **float 类属性只能经 XML 反序列化设置**（Lua 的 Variant 是 double，`SetAttribute` 对 float 属性会被拒）⇒ **改光照/雾参数的正确姿势是自带一份 LightGroup XML**，而不是脚本里 `set`。脚本里能 set 的只有部分 Lua 暴露字段。

## 3. 光照侧的对照刻度（L0–L4，与几何刻度平行）

| 级 | 判据 | 形态 |
|---|---|---|
| L0 契约冻结 | 契约清单逐项齐全且版本化 | 布尔 |
| L1 通道隔离 | 每个机位有 A / B / C 三通道留证（或声明为何缺） | 布尔 |
| L2 单光源归因 | 逐光源各出一帧（one-light-at-a-time），差异可归因到具体光源 | 计数 + 帧 |
| L3 光照不变量 | 见下表：能在参考图上量、且**与后期无关**的量 | 数值 |
| L4 后处理 | 单独一层，**不参与 L3 判定** | 见第 6 节 |

### 3.1 L3 光照不变量（可量的外观证据）

| 量 | 怎么量 | 惯例起点（非门禁） | 说明 |
|---|---|---|---|
| 影长/物高比 | 已知高度物体的影长 ÷ 高度 = `cot(太阳高度角)`（正射视图上直接量像素） | 相对误差 ≤ 10% | 反推太阳高度角，与契约对账 |
| 阴影方位角 | 影子的水平朝向 | 偏差 ≤ 5° | 与太阳方位角对账（差 180°） |
| 明暗交界线位置 | 圆柱/球类构件上明暗分界的像素位置 | 位置偏差 ≤ 2% 图宽 | 与光源方位一致 |
| 镜面高光质心 | 高光斑的质心与面积 | 质心漂移 ≤ 2% 图宽 | 对光源方位与表面法线高度敏感 |
| 凹角环境遮蔽 | 已知凹角处在 A 与 B 通道的亮度差 | 对比度落在自检值 ± 40% | 检验 ambient/SH 是否注入 |
| 距离—对比度衰减 | 已知距离的参考板在 B 通道的对比度 | 采样点相对偏差 ≤ 15% | 反推雾参数 |
| 中性灰响应 | 中性灰参考面的 RGB 比 | 比值偏差 ≤ 5% | 反推色温/白平衡 |

“惯例起点”是外部实践的常见量级，**不是本工程门禁**。进门禁前三个前置条件缺一不可：①在参数表登记符号与口径；②用**自己的正交渲染当控制组先做方法自检**（同 `10` I-07：方法自检未过时只能说“方法不可用”，不能说“参考侧不可测”）；③留下“这条能拦住而上一代没拦住”的负样本。

### 3.2 新增有效性闸（与 `14` 的跨域 IoU 闸同级）

> **光照契约不等价 ⇒ 一切图像相似度指标作废。**
> 这是一道**布尔闸**，判据是契约清单逐项相等，不是"看起来差不多"。

理由：tonemap、bloom、自动曝光都是**非线性且不可逆**的。两帧光照不同却去比 SSIM/直方图，得到的数字没有意义。

## 4. 外观侧的归因路由

| 症状 | 最可能原因 | 看哪个通道 |
|---|---|---|
| 整体偏亮/偏暗 | 曝光 / tonemap / 亮度 | C 与 B 差分 |
| 阴影方向不对 | 主光方位与契约不符 | B 的影长比与方位角 |
| 阴影锯齿/漏光 | 阴影分辨率、bias、体素阴影体查询档 | B |
| 远处发灰发白 | 雾参数（深度雾/高度雾） | B 的距离—对比度曲线 |
| 近景糊、远景锐（或反之） | DOF / 模糊类后期 | C 与 B 差分 |
| 高光位置不对 | 光源方位或表面法线 | B 的镜面质心 |
| 颜色比例不对但明暗对 | **材质 albedo**（不是光照） | A 通道 |
| 边界处有渐进暗环 | vignette | C |
| 高亮区域粘连成团 | bloom 阈值/权重过高 | C |
| 暗部糊成一片 | 自动曝光在场景内漂移 | B（关自动曝光后复测） |

## 5. 后处理纪律（五条）

本节的“冻结项”只表示当前机位的比较契约与版本快照；换后处理参数时应保留旧证据、生成新版本并重跑受影响机位，不得据此宣称后处理或通道永久不可改。

1. **后处理属"机位级"冻结项**：换 tonemap/bloom 等于换相机，旧基线全部作废（与 `10` I-03"工具一改就重立基线"同构）。
2. **后处理会掩盖缺陷**：bloom 盖体素锯齿、DOF 盖远处 LOD 接缝、tonemap 盖过曝、vignette 盖边角错误 ⇒ **验收先关后效跑一遍，再开后效出成片**。
3. **逐像素验收只在同一 RenderPath 版本内成立**（`10` I-03 / I-04）。
4. **后处理参数属主数据**，要版本化、可回滚。
5. **不得用后期调色去掩盖材质错误**；材质错误要在 A 通道上先关闭。

## 6. 后处理开关清单（引擎已暴露，逐项都要进契约）

按引擎的 Zone 组件字段整理；**每项都要在契约里写明开/关与数值**，因为任一变化都会让上一轮像素基线失效。

| 类别 | 项目 |
|---|---|
| 色调 | tonemap 模式、tonemap LUT 开关 |
| 泛光 | bloom 阈值/权重/强度、bloom 模式（含 UE 风格一套参数） |
| 曝光 | 自动曝光开关 |
| 环境遮蔽类 | SSAO 半径/强度、SSGI 开关/质量/强度、SSR 开关/是否用上一帧颜色 |
| 运动 | 运动模糊开关/强度/最大畸变 |
| 抗锯齿 | FXAA 开关 |
| 画面框 | vignette 开关/强度/贴图 |
| 景深/模糊 | 全屏高斯模糊（菜单虚化类） |
| 风格化 | toon 着色参数（明暗分界、阴影 HSV、边缘光、深度描边） |
| 大气（非后期但同属外观） | 体积雾及其对光源颜色的覆盖、方向光散射色、天空光体积散射强度 |
| 深度阴影 | depth shadow 的 influence / threshold / fade range |

## 7. 引擎入口：唯一出处是 `15` §1.7

**引擎侧的旋钮、默认值、平台差异与陷阱，本文件不重复，唯一出处是 `15-urhox-native-capabilities.md` §1.7（光照与后处理）。** 本节只留三条**方法上必须知道、否则三通道纪律做不出来**的事实：

| 方法上必需的能力 | 为什么它决定方法论可行 | 详细入口 |
|---|---|---|
| **无光照通道材质存在** | 没有它就没有 A 通道 ⇒ 几何结论无处可采 | `15` §1.7 最后三行 |
| **RenderPath 可按 tag 整组启停** | 没有它就无法“关后效验收再开后效出片” | `15` §1.7 “RenderPath 冻结/启停”行 |
| **大气/环境光只能做在主数据文件里**（float 属性不走 Lua；SH/IBL 未暴露） | 决定“光照契约”到底是**一个可哈希的文件**，而不是一堆运行时参数（这是第 2 节与第 6 节能成立的前提） | `15` §1.7 前三行 + “float 属性”行 |

另：体素领域的 DDA 通道与体素阴影体会**改变光照通路**（见 `15` §1.1/§1.2）⇒ 开或关它们等于换渲染路径，同样要进契约。

## 9. 反面清单（每条带真实后果）

1. **用成片（后效全开）判几何** —— bloom 与 DOF 会吃掉体素锯齿与 LOD 接缝，判出来的"通过"是假的。
2. **在光照不同的两帧上算 SSIM/直方图** —— 非线性后期不可逆，数字无意义。
3. **另建 Zone 覆盖 LightGroup，然后说"IBL/SH/Bloom 丢了"** —— 是自己用 priority=0 顶掉了 priority=-1 的预设 Zone。
4. **脚本里 set float 光照属性** —— 会被拒或静默无效（Variant 类型不匹配），必须走 XML 主数据。
5. **换 tonemap / bloom 后沿用旧逐像素基线** —— 基线失效，必须重立。
6. **拿体积雾/上帝光当"光照对"的证据** —— 那是大气散射，不是光照几何。
7. **用 LUT 调色掩盖材质错误** —— 材质问题必须在 A 通道上先关。
8. **只留 C 通道** —— 该机位没有几何证据，等于没拍。

## 本文件的通用性边界

- 第 1–6 节（三通道纪律、契约清单、L 级刻度、归因路由、后期纪律）是**方法**，与引擎无关；换引擎只需重填第 7 节的入口。
- 第 7 节的 API 绑定某一发行版；换发行版必须重跑 `scripts/urhox_capability_probe.py` 并重核 Zone/Light 字段。
- 本文件不覆盖：音频、UI、粒子特效的保真——它们不是"复刻对照"的一部分。
