# 总流程、轮次协议、状态语义与性能口径

本文件是**流程调度与语义**的唯一出处：阶段划分、轮次协议、参考登记点、状态枚举、性能必录项。具体阈值与项目取值一律来自项目参数表（`SKILL.md` 第 2 节），本文件不预设任何数值。

本文件中的“冻结/FROZEN”是历史流程词：默认只表示参考取值或版本基线已记录，**不是 AI 对几何、材质、通道或结论的主动冻结**。版本基线是可回滚快照；新证据或更像的改动可以产生新版本。只有用户明确要求停止/交付，才可进入收口。

本文件**不是门禁成员表**：门禁的唯一来源是 `references/04-verification.md` 的四张检查表。

## 0 先纠正一个常见误解：不要把它当成四步流水线

“检索 → 分析 → 引擎操纵 → 验证，不通过就退回检索/分析”这个四步模型**方向对、但会漏掉四处硬约束**，而漏掉的地方正好是事故高发区。

| 四步模型 | 本流程对应 | 漏了什么 |
|---|---|---|
| （无） | **G0** 对象类型/尺度/口径/参数表/性能门槛登记 | 不登记就取证 ⇒ 证据类型错配（如拿照片证明地形高程），当轮证据作废重建 |
| 1 检索 | **G1** 参考资料包 + 来源分级 | 缺“来源分级 + 缺口登记” |
| 2 分析 | **G2** 制图 + **唯一坐标注册版本基线** → 才是 G3/G4 | “分析”的**产物是可追溯的注册变换版本**；把 G2 并进去 = 没有基线 ⇒ 多处各自维护缩放、全局比例漂移 |
| 3 操纵 | **G3/G4/G7** | 顺序固定：先基准面/边界/主体量，再构件与装饰 |
| 4 验证 | **G5 → G6 → G7**，**四类门禁分开** | 合成一句“验证通过”就会把 C 类（视觉/语义）当 A 类（空间）用：拿透视截图当正交投影、拿“看着像”替代占用与接地读数 |
| 不通过回退 | **按症状分层回退** + **两轮无改善即停** | 回退粒度太粗：“不通过就重检索”会把本该回高度带/碰撞代理/注册层的失败，全部变成重做取证 |

三处额外缺失：

1. **证据必须与生产不同源**：空间类结论要用**独立运行时投影**（从最终体素网格导出），禁止用布局脚本自己的多边形自证；每机位要三件套、指标要均值 + 最差项（见 `04` §0/§6、`07` §2）。
2. **没有“运行通道”就验不完整**：离线全绿 ≠ 运行起来能看；烘焙节点命名、出生点、相机接管、编辑器资源扫描这四类只在运行通道暴露（见 `12-channel-divergence.md`）。
3. **循环是有界的**：不是无界回退——一轮只改一个变量，第 2 轮仍无改善就停并升级（见本文件 §4 第 4 条）。

修正后的骨架：

```text
G0 登记口径/对象类型/尺度/参数表/性能门槛
 G1 检索取证（来源分级 + 缺口登记）
 G2 分析 + 制图 + 唯一注册  ★版本基线
 G3 基准面/边界/主数据灰盒 → G4 构件与装配
 G5 体素工程门禁 / G6 独立投影+空间+视觉 / G7 玩法物理+烘焙+归档
回退：按症状回对应层；两轮无改善 → 停并升级复盘
```

## 1. 四种质量层（不可互相替代）

| 质量层 | 回答的问题 | 主要证据 | 不能被什么替代 |
|---|---|---|---|
| 空间忠实度 | 对象轮廓/边界、高差与主数据要素是否在正确位置？ | 注册平面、正交投影、轮廓重叠率与边界距离、锚点误差 | 透视截图、主观感觉 |
| 体素工程质量 | 网格、占用、层级、构建是否严格、确定、无冲突？ | 整数原点、单位缩放、占用审计、接地报告、重建哈希、构建日志 | 空间布局指标 |
| 视觉与语义忠实度 | 对象的关键特征能否被识别，风格、层级、叙事是否成立？ | 多机位截图、立面/剖面、关键特征清单、差异图 | 只看俯视足迹 |
| 运行时产品质量 | 能否走、挖、炸、补，是否稳定可交付？ | 运行时烟测、破坏测试、性能记录、最终场景状态 | 离线截图 |

四层全部通过时，才可以在**用户要求的验收口径**下写“当前版本整体 PASS”。任一层缺失时结论必须降级为 `PASS-WATCH` 或 `BLOCKED`；AI 不得自行把它写成“复刻完成/已定案”。

| G3 | 基准面/边界/主数据要素灰盒与主体量 | `04` 表 A | — |

## 3. 每阶段的输入、输出、门禁与失败处置

**门禁列的含义统一为：该阶段对应的检查表全部通过。** 本文件不列举门禁成员（唯一来源见 `04`）。

| 阶段 | 输入 | 输出 | 门禁（= `04` 对应表全通过） | 失败处置 |
|---|---|---|---|---|
| G0 | 复刻对象、用途、目标平台与硬件、预期视角、玩法范围 | 任务书、验收指标表、初始风险清单、**填好的项目参数表**（字段见 `SKILL.md` §2，含与 `04` §0 符号 1:1 的阈值登记） | 登记动作完成：口径/性能目标/对象类型/尺度已记录，阈值登记表与 `04` 正文符号差集为空 | 正式结论缺字段时停在 G0；可逆探索另标 `EXPLORATORY`，不要猜值混入正式链 |
| G1 | 官方/公开资料与在线影像、测绘数据与图纸、多角度照片、同类参照、设定稿 | 参考包、来源分级表、按对象类型的主数据表、可用于注册的测量图与剖面/切面 | `04` 表 A 前置 + `01` 参考包状态达标 | 缺资料时显式标记缺口；禁止把推断伪装成官方数据 |
| G2 | 通过的参考包 | 唯一注册变换、按对象类型的图纸集、带版本的 `transform_id`、注册基线登记（落点见 `07` §2） | `02` §7 的 `ED-F1`–`ED-F3` 全通过 | 注册漂移时回退到最近一个 `PASS` 版本并评审；也可在用户目标下生成新版本，不得把旧基线当成不可改 |
| G3 | 注册版本基线 + 图纸 | 基准面、边界、主数据要素灰盒、主体量、硬锚点定位 | `04` 表 A 的空间项通过 | 全局比例或拓扑错误时暂停细节建模，先修注册 |
| G4 | G3 灰盒 + 资产语法 | 构件、组团、装配后的完整场景 | `04` 表 A/C 相关项通过；资产按“主体/细节/动态”分层并走统一最终化出口 | 局部收益导致全局门禁下降时回退该局部 |
| G5 | 装配后的场景 | 占用审计、接地审计、网格严格性报告、语义检查 | `04` 表 B 全部 11 项通过 | 任一硬指标不达标即 `BLOCKED`，不得用主观观感放行 |
| G6 | 最终体素网格 | 运行时正交投影、剖面/立面叠加、多机位截图与差异图、指标 JSON | `04` 表 C 通过；投影源与注册同源、机位参数可复现 | 投影源为空或与生成数据不同源时，本节结论全部作废 |
| G7 | 可运行场景 | 破坏/碰撞烟测、动态体回收数据、烘焙日志、性能记录、最终场景状态 | `04` 表 D 通过（含三证合一，若玩法含破坏）；烘焙幂等；场景唯一 | 只证明了几何没证明碰撞时记为未通过 |

G0 与 G2 是**参考登记/版本基线点**：记录确认人与时间，便于追溯和回滚。修改时生成新版本并保留旧快照；这不构成 AI 对模型保真推进的禁止。

## 4. 轮次协议与升级阶梯

一轮迭代只允许一个主问题。写清下面六项后才可以动手：

```text
目标对象：
当前基线（tag / 版本 / 哈希）：
本轮唯一问题：
本轮参照基线（用于归因，不代表以后不可改）：
输入证据：
成功门槛（一个可测指标 + 一个可观察结果）：
```

规则：

1. **单变量**：一轮只改一个变量；同时改注册、体素和材质会让指标变化无法归因。
2. **可回滚**：动手前记录可回滚点，改动后给出回滚命令（备份与校验值登记位见 `07` §2）。
3. **变更分级**：按项目定义的变更类别登记，并据此选回归范围；跨类变更必须扩大回归矩阵。
4. **两轮无改善的升级阶梯（本规则为唯一出处）**：
   - 第 1 轮无改善 → 记录差值，允许换一个更小范围再试一轮；
    - **第 2 轮仍无改善（两个指标口径都无改善）→ 停止加细节，升级为复盘项**：重新确认根因与修复层级，把未验证假设隔离并标记未知；不要继续堆无证据细节；
   - 出现“局部改善但全局门禁下降” → 立即回退该局部，不得继续叠加；
    - 需要修改参考登记内容（注册变换、硬锚点、口径）→ 记录影响并生成新版本；不得静默覆盖旧基线，但也不得把旧基线解释成永远不能改。
   - `references/06-visual-fidelity-loop.md` 与 `04` §8 只引用本阶梯，不另设判据。
5. **交接六问**：改了什么、为什么改、证据是什么、指标如何变化、未关闭风险、下一轮做什么。缺一项即视为未交接。
6. **口径不可悄悄变**：指标定义、采集方式或阈值变化时，在 `07` §3 的迭代记录里同时保留旧值、旧定义、修订原因与新值。

## 5. 状态语义与枚举映射

**门禁状态只有四态**，含义固定：

| 状态 | 含义 | 允许的动作 |
|---|---|---|
| `PASS` | 该门禁全部指标达标且证据可复现 | 可写入正式基线 |
| `PASS-WATCH` | 主要指标达标，但存在未关闭风险或证据链不完整 | 可继续推进；必须登记风险项 |
| `BLOCKED` | 存在硬指标不达标或证据缺失 | 停止推进该方向；先修复或降级范围 |
| `EXPLORATORY` | 试验性尝试，未进入正式口径 | **不得写入正式基线** |

其它体系的状态一律按下表映射到四态；**映射表是唯一权威**，专项文件只能引用、不得自定义等价状态：

| 专项体系 | 出现位置 | 取值 | 映射 |
|---|---|---|---|
| 参考包状态 | `01` §17 | `COLLECTING` | `EXPLORATORY` |
| 参考包状态 | `01` §17 | `NORMALIZED`、`CROSS_CHECKED` | `PASS-WATCH` |
| 参考包状态 | `01` §17 | `PASS` | `PASS` |
| 参考包状态 | `01` §17 | `BLOCKED` | `BLOCKED` |
| 参考包状态 | `01` §17 | `SUPERSEDED` | 无门禁含义（只读历史） |
| 图纸/注册状态 | `02` §3 | `DRAFT` | `EXPLORATORY` |
| 图纸/注册状态 | `02` §3 | `REVIEW` | `PASS-WATCH` |
| 图纸/注册状态 | `02` §3 | `PASS`、`FROZEN` | `PASS`（`FROZEN` 仅表示该注册/基线版本已记录，语义上不表示模型完成或不可修改） |
| 图纸/注册状态 | `02` §3 | `VOID` | `BLOCKED` |
| 图纸/注册状态 | `02` §3 | `SUPERSEDED` | 无门禁含义（只读历史） |
| 日志/错误分级 | `05` §12 | 阻断 | `BLOCKED` |
| 日志/错误分级 | `05` §12 | 功能风险 | `PASS-WATCH`（须能复现且已登记） |
| 日志/错误分级 | `05` §12 | 可降级 / 债务 | `PASS-WATCH`（登记后允许推进） |

迁移规则：

- `EXPLORATORY → PASS` 必须补齐正式口径的采集与证据，不能因为“看着更好”跳级；反过来，正式链暂缺证据也不阻止另开 `EXPLORATORY` 做可逆保真探索。
- 任一质量层链路断裂（空间正确、视觉可读、运行时可复现之一），最高只能 `PASS-WATCH`。
- `BLOCKED` 解除必须附修复前后的同口径读数。
- 状态只能由证据推动，不能由进度压力推动。

## 6. 每轮必须记录的性能与稳定性读数

门槛在 G0 参考登记（写进参数表的“性能门槛”）；**未登记前**每轮仍必须记录下列 9 项原始读数，采集方式与落点固定：

| # | 读数 | 采集方式 | 落点 |
|---|---|---|---|
| 1 | 首次对象/场景生成耗时 | 生成入口前后打点（引擎日志时间戳差值） | `perf_<tag>.json` → `first_build_ms` |
| 2 | 体素物理世界 finalization 耗时 | finalization 调用前后打点 | `physics_finalize_ms` |
| 3 | 峰值内存 | 引擎内存统计或进程峰值采样 | `peak_memory_mb` |
| 4 | 代表机位平均帧率 / 1% low 或 P95 帧时 | 固定机位 + 固定时长采样，取均值与尾部值 | `fps_avg` / `frame_p95_ms` |
| 5 | 单次挖掘/爆破/补石的 P50 与 P95 延迟 | 每次操作打点，按操作类型分组统计 | `edit_p50_ms` / `edit_p95_ms` |
| 6 | 动态体峰值数量 | 每帧或每次生成后取最大值 | `dynamic_peak_count` |
| 7 | 破坏后几何与碰撞更新时间 | 破坏触发到重建完成的时间差 | `rebuild_after_break_ms` |
| 8 | 运行时启动到就绪的耗时 | 启动标志到就绪标志的时间差 | `startup_to_ready_ms` |
| 9 | 体积数与占用体素数 | 审计输出 | `volume_count` / `occupied_cells` |

执行与记账规则：

- **“减少不必要的重复体积”必须落成可判定的动作**：统计同一批次的重复重建次数与重复体积 hash 数，重建次数或重复体积数下降才算优化；无法给出前后读数的“优化”不登记。
- 优化顺序固定：① 减少重复体积与重复重建 → ② 脏区更新与分块材质化 → ③ 单点算法。跨顺序优化会把“重建次数减少”误记成“算法变快”。
- 读数为 0 或缺失时，在 `perf_<tag>.json` 里写 `null` 并注明原因，不得省略字段、不得用估计值填充。

## 7. 已删除的规则

原“计数与判定口径”（要求任何“有 N 条/N 处”的结论注明计数口径、固定前缀与期望值）属文档自指规则，不产出任何资产或门禁，已于 2026-09-22 整体删除。若某轮确实需要统计类证据，按 `07` §5 的清单脚本产出，不额外发明计数规则。

## 8. 本文件的通用性边界

- 阶段编号、四态枚举与性能读数清单是方法论约定，不是引擎能力；换引擎或换团队可改名但必须保留语义，且映射表必须同步更新。
- 具体阈值、指标定义、目标硬件与变更分级表来自项目参数表；本文件不提供任何默认数值。
- 专项门禁家族（`REF-F*`/`ED-F*`/`F0`–`F5`）的细节由 `01`/`02`/`06` 定义；本文件只负责把它们挂到 G0–G7 上。

## 9. 对象类型与尺度如何影响阶段裁剪

对象类型与尺度等级在 G0 与参数表一并冻结（分类与取值见 `08` 第 2、3 节）。裁剪只作用于**检查项与证据形式**，不作用于证据标准与四态语义。

1. **主数据形态决定 G1–G3 的证据类型。** 可测指标：参数表“主数据形态”字段已填写（布尔）。可观察结果：G1 产出的主数据表能被 G2/G3 直接消费，且 G2 冻结的 `transform_id` 与它同源。失败处置：字段为空即停在 G0，禁止用“参考照片 + 主观判断”替代注册基准。
2. **对象类型决定哪些检查项适用、哪些必须替换。** 可测指标：每个裁剪项在参数表中写成 `裁剪项 | 理由 | 替代检查项 | 确认人`，缺段数 = 0（见 `08` 第 5 节）。可观察结果：被裁剪项的替代检查出现在对应阶段的输出里。失败处置：缺任一段视为漏检，该阶段门禁最高只能 `PASS-WATCH`。
3. **尺度等级决定体素尺寸与细节预算。** 可测指标：体素尺寸 ≤ 最小可辨识构件的 1/3（最小可辨识构件字段已填）；参数表的细节预算三项上限均已给出数值。**可观察结果（判定方法固定）**：在 G5 的占用/接地报告里，逐项指出“最小可辨识构件”的对应体素范围，并附一张正交近景截图；评审者按该截图与范围标注判定可否分辨，判定结论写入迭代记录。失败处置：无法分辨时显式降低细节目标并登记该降级，不得默默放宽阈值。
4. **不可裁剪项与类型、尺度无关。** 可测指标：注册同源性、占用重叠、悬浮/下陷/越界、接地或贴合、根节点唯一性与构建幂等、固定机位参数可复现、动态体有可见渲染面、指标与证据可追溯，这八类在参数表中被列为裁剪项的计数 = 0（“破坏三证合一”仅在玩法含破坏时适用）。可观察结果：G5、G6、G7 的门禁在这些项上给出读数。失败处置：任一项被裁剪即判本文件门禁无效，回到 G0 重定范围。
5. **跨尺度拼接必须显式允许。** 可测指标：参数表已声明允许的跨级组合（如大尺度场景内的微物件）。可观察结果：跨级物体附有“可辨识性由什么保证”的说明。失败处置：未声明即按尺度溢出处理，回到 G0 重新分配细节预算。
6. **裁剪不改阶段编号。** 可测指标：G0–G7 编号与四态枚举在裁剪后保持原样（布尔）。可观察结果：裁剪后的轮次记录仍能按同一编号交接。失败处置：出现自定义编号时先恢复本文件编号，再补裁剪登记。
