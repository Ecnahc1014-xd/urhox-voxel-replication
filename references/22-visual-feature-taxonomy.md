# 视觉特征词表（图像驱动重建 · 阶段Ⅰ 的标签体系）

本文件回答：**一张参考图"是什么风格/什么特征"该怎么写下来**，以及**这些标签能用来做什么、绝对不能用来做什么**。

分工（不重复正文）：

- `19-reference-image-intake-gate.md`：一张图**能不能当输入**（角色、可量测性、正交基底）。本文件管的是**它是什么**。
- `01-reference-evidence.md`：来源**等级与证据资格**。
- **本文件：特征的命名、冻结词表与标签 schema。** 标签是**描述符**，不是证据。

## 0 四条纪律

1. **标签是描述符，不是证据。** 任何几何结论必须回到 `01` 的等级链；"这是赛博朋克风"不构成任何尺寸/形状依据。
2. **词表必须冻结。** 跨轮比较只有在词表版本相同时才成立；新增词条要走 §4 的登记流程，不得临场造词。
3. **照片定不了真彩。** 借鉴外部纪律（室内类技能明确写 *"Never call true color, undertone, or sheen from a photo"*）：
   从照片只能标**相对色相/明度关系**，不得标"实际色号"。
4. **渲染图不是色彩参考。** 引擎渲染受光照/后处理影响，只能标"在该光照条件下的呈现"，不能当作材质基色。

## 1 六个轴（标签只许落在这六轴上）

| 轴 | 代号 | 回答什么 | 典型取值来源 |
|---|---|---|---|
| 形态 | `form` | 体量、轮廓、比例、层叠关系 | 正交/轴测视图、剖面图 |
| 材质 | `material` | 表面材质类别与工艺 | 特写图、材质图集 |
| 光照 | `lighting` | 光位、光比、时段、色温倾向 | 实拍与渲染帧 |
| 色彩 | `color` | 相对色相关系（冷暖、明度区间）——**不是色号** | 仅作相对描述 |
| 构图 | `composition` | 画幅、视点、主体占比、分幅方式 | 全部参考图 |
| 风格 DNA | `style_dna` | 制作语境（时代/产地/预算/工艺感） | 设定图、风格宪章类文档 |

> 六轴的分工理由：前三轴影响**几何与外观**，后三轴影响**检索与生成约束**。混轴会让标签既不能对账也不能检索。

## 2 冻结词表 v1（2026-09-23）

**状态**：`v1` 为**首批可冻结版本**；每条都标了来源与"能否作为量测依据"。
**新增/修改**必须同时更新 `assets/feature-taxonomy-v1.json` 与本表（两处同源，`--check` 会校验）。

### 2.6 `style_dna` 风格 DNA（借鉴 `low-budget-3d` 的"风格宪法"结构化写法）

| 术语 | 说明 | 来源 |
|---|---|---|
| `era:*` | 制作时代语境（如 `early_2000s`） | `low-budget-3d/references/style-constitution.md` |
| `density:low` | 面数/细节密度档 | 同上（`polygon_density`） |
| `topology:simple` | 拓扑简化程度 | 同上 |
| `proportions:stylized` | 比例风格化程度（含 `awkward` 一类负向描述） | 同上 |

> `style_dna` 允许**负向取值**（如 `proportions: awkward`）。这是 `low-budget-3d` 的可取之处：
> 把"廉价感"也写成可复现的参数，而不是靠形容词。**我们复刻时应同时登记"要复现的"与"要避免的"**。

## 3 标签 schema（机器可读）

落在参考包旁路的 `feature_tags.json`（**不写进 `reference_manifest.json`**，避免与入包闸的角色/部件数语义混在一起）：

```json
{
  "schema": "urhox-feature-tags/1",
  "taxonomyVersion": "v1",
  "frozenAt": "2026-09-23",
  "images": [
    {
      "file": "_src/img/71701380_04.jpg",
      "axes": {
        "form": ["layered-tier"],
        "material": ["tile-blue", "metal-gold-trim"],
        "lighting": ["night-scene"],
        "color": ["cool-dominant", "warm-accent"],
        "composition": ["front-elevation"],
        "style_dna": ["era:modern"]
      },
      "provenance": "human",
      "note": "只标可见项；不确定的轴留空，不得猜"
    }
  ]
}
```

规则：

- **留空是合法值**，猜是非法值；没有把握的轴必须留空。
- `provenance` 只许 `human` / `rule:<id>` / `external:<source>` 三种；`rule:` 与 `external:` 的标签在用于决策前必须人工复核。
- 每个标签必须能在 §2 的表里查到；查不到就是非法标签（`--check` 会报）。

## 4 新增词条的流程

1. 写清**轴**、**术语**、**来源**（哪个包哪个文件）、**可否量测**（能给出量测方法就写方法）。
2. 同时更新 `assets/feature-taxonomy-v1.json` 与本表 §2。
3. 术语一旦发布**不得改义**；要改就发 `v2` 并在 `assets/` 里并存，老包仍指 `v1`。
4. 跑校验（见 §5）：两处必须一致。

## 5 校验

```bash
PYTHONUTF8=1 python scripts/feature_taxonomy_check.py
PYTHONUTF8=1 python scripts/feature_taxonomy_check.py --tags <feature_tags.json> --json
```

- 比对 `references/22-*.md` 的 §2 表格与 `assets/feature-taxonomy-v1.json` 的词条集合；
- 重复术语、缺来源、缺 `measurable` 字段、两处不一致 → 非零退出。
- --tags 才检查实际标注文件的 schema、taxonomyVersion、各轴词条与 provenance；允许空轴，era:* 只接受明确的非空后缀。词表/schema 合法不等于视觉标注正确，仍须看原图复核。

## 6 用途与**禁止用途**

| 可以 | 不可以 |
|---|---|
| 检索与分组（"所有夜景正立面"） | 作为尺寸/形状依据（那是 `01` 的证据链） |
| 跨轮可比的分组键（同词表版本下） | 跨词表版本直接比较计数 |
| 给生成器提供约束（风格、配色倾向） | 当作"已复现"的判据（那是 `04` 的四张表） |
| 标注"这张图只能提供什么"（配合 `19` 的角色矩阵） | 用标签替代 `19` 的可量测性判定 |

## 7 已知局限

1. 词表 v1 是从**已收参考包**里归纳的（含 `low-budget-3d` 的风格宪章、`cyberpunk/neon/steampunk/ink/gothic` 的严格风格强制句、室内类技能的光色纪律），**尚未覆盖**写实/现代都市/科幻巨构等方向。
2. `color` 轴**故意不给可量测项**：照片与渲染都不能定真彩，给“可量测”是假精确。
3. `style_dna` 借鉴的是低成本动画语境，迁到其它语境需要重新定义取值域。

## 8 打分式现场特征提取（**照片 → 结构化评分**）

从照片里提特征，除了贴标签（§1–§3），还可以走**打分**路线。该框架来自外部参考包
（城市更新现场分析类技能），本工程采纳其**维度与打分方式**，不采纳其具体阈值：

| 维度 | 看什么 |
|---|---|
| 整体环境 | 场地与周边的空间关系、可达性、噪声/氛围 |
| 结构形态 | 体量、层数、结构表达 |
| 立面 | 材质分区、开口节律、色彩关系 |
| 硬质景观 | 铺装、台阶、挡墙、井盖一类固定件 |
| 家具与设施 | 灯、椅、栏杆、标识——**可移动**与**固定**要分开 |
| 绿化/植被 | 类型、密度、层次、季相 |

**规则**：

- 每维 **1–5 分**，并给**综合分**；每维必须写清“这个分是因为看到了什么”（不可只给分）。
- 分值**不得**直接当作几何结论：它是**优先级排序器**，用来决定先做哪一块，不是尺寸依据。
- 打分必须带**拍摄条件**（时段/光照/天气）——同一场地不同光下的观感差异可以很大。
- “策略按严重度校准”这个机制可取：低分维度优先处理，但**不得**由分数反推绝对尺寸。

## 9 艺术指导合同（出图/海报类交付的纪律）

来自“营造”类参考包（中文建筑与在地文化照片 → 编辑海报）。它对**风格化交付**定了一份可检验的合同，
其中与体素交付相通的部分值得采纳：

| 合同条 | 内容 | 为什么对我们也适用 |
|---|---|---|
| 命题先于检索 | 先写清“主体如何处理 / 背景如何主动参与 / 文字如何与真实轮廓互动 / 哪个非默认动作破除对称” | 与 G0 的口径冻结同源：**先定命题再找素材**，否则素材反过来左右目标 |
| 素材分工固定 | 校正原图 / 一张主导参考 / 稀疏排版垫图，**不得互相替代、改序** | 对应本工程的“参考分级 + 单一注册链” |
| 每个约束必须归类并指向垫图区域 | 约束不得散落在提示词里，必须每条都有归属与位置 | 对应“参数表里每个字段都有唯一消费方” |
| 设计说明必须结构化落盘 | `recipe.json` + `design-plan.json` | 对应证据包里的几何源与指标 JSON |
| **“两座孤岛”默认无效** | 主体居中 + 标题居中且互不接触 = 默认不通过 | 提醒：**“各自看起来都对、彼此没关系”是失败态**，需要显式的相互作用 |
| 单图各域须在**缩略尺度**可见 | 主体域/背景域/互动域在缩小后仍能读出来 | 与“多机位 + 最差项”同一思路：**先在粗尺度站得住，再谈细节** |
| 提示词只表达一个艺术方向 | 不拼约束、失败案例、验收清单 | 与本文件 §0 纪律 1 同：标签与约束各归其位，不得混写 |

**采纳尺度**：这些是**流程纪律**，不是几何判据——不得写成 `04` 的门禁项。
