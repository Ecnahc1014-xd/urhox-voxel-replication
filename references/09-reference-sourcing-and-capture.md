# 参考图取数：站点目录、检索语法、抓取与截图方法

本文件解决**"去哪找、怎么搜、怎么抓、怎么截"**；证据的**判定标准**（来源分级、标定、冲突、评分、污染旗标、追溯链）由 `references/01-reference-evidence.md` 定义。两者是同一件事的两半：09 产出原始素材，01 决定它能不能当证据。

**接口约定**：本文件产出的每份素材必须能直接被 01 消费——带 `source_id`、原图只读、来源 URL、抓取时间、版本/日期、能回答与不能回答的问题；缺任何一项，抓回来的图只能算"灵感收藏"，不能进参考包。

## 1. 站点分类目录（按**用途**分类，不按网站名气）

| 用途类别 | 代表平台 | 适合回答 | 不适合回答 | 常见等级倾向 |
|---|---|---|---|---|
| 官方一手 | 官方站点、官方百科/wiki、官方地图（交互式）、官方画集/设定集扫描、官方开发者文档 | 命名、方位、轮廓、版本事实、权威设定 | 可施工的精确尺寸、室内结构、被版本改掉的历史形态 | A |
| 百科与粉丝 wiki | MediaWiki 系（Fandom/Wikia 等）、维基百科、Wikimedia Commons、萌娘百科类 | 结构拆解、构件命名、专题条目、分类页成组取图 | 权威尺寸；同人推测内容常与官方混排 | B（官方内容可 A） |
| 地图与测绘 | OpenStreetMap、Wikimedia Maps、Mapcarta、Wikimapia、商用地图（Google/Bing/Apple）、历史地图档案、地形/DEM 门户 | 平面轮廓、路网、方位、高程与水体 | 建筑立面与构件细节 | A/B |
| 社区论坛与问答 | Reddit、公开 Discord 存档、贴吧、NGA、机核、知乎、StackExchange 系 | 缺口补全、玩家重建、构件细节照片、工具问题解法 | 整体比例与硬锚点；帖子常夹带主观改造 | B/C |
| 图库与作品集 | Flickr、Wikimedia、Pinterest、DeviantArt、ArtStation、Pixiv | 多角度外观、材质与配色灵感、风格参照 | 空间关系（透视强、无标定） | B（AI/同人 → D） |
| 视频平台 | YouTube、Bilibili、Niconico 等 | 连续视角、通行路线、遮挡关系、动态表现 | 精确尺寸；必须抽帧并记时间码 | B/C |
| 3D 与模型库 | Sketchfab 类、开放素材库、城市开放数据/GIS 门户（建筑轮廓、DEM） | 体量、部件拓扑、可复用轮廓与高程 | 风格一致性与合法性需逐项确认 | B/C |
| 聚合与转载 | 搜索缩略图、转载站、图片聚合站、AI 生成图站 | 只用于找线索、反查原始出处 | 任何直接证据 | C/D |

用法：

1. **先按"我要回答什么问题"选类别**，再选具体站点；不要按"哪个站图多"开工。
2. 同一问题至少跨**两个类别**取证（例如轮廓来自地图类、立面来自图库类），单类别结论按 01 §9 记入冲突表。
3. 聚合/转载站的图必须回查到原始出处（见第 2.4 节反查），查不到就按 D 级处理。

## 2. 检索语法与组合

### 2.1 通用搜索引擎

```text
site:<域名>                     限定站点（对论坛/wiki 最有效）
filetype:pdf|jpg|png|svg        找图册、图集、图纸、矢量图
intitle:<词>                    标题命中（找"地图""平面图""设定集"）
inurl:<词>                      路径命中（找 gallery / map / wiki 分类页）
"<精确短语>"                     官方名、专用术语
<词A> OR <词B>                  同义/多语言变体
-site:<域名>                    排除聚合站与转载站
<词> after:<YYYY-MM-DD>         版本变更后（游戏更新/改版）
```

### 2.2 组合矩阵（与 01 §2 的搜索四元组对齐）

```text
<对象名> × <视角/结构词> × <资料类型词> × <语言/版本>
```

- 对象名要多套：官方名、社区常用名、俗称、外文名、旧版名（改版会改名）。
- 视角/结构词：`top view`、`aerial`、`map`、`floor plan`、`elevation`、`section`、`blueprint`、`orthographic`、`四视图`、`三视图`、`立面`、`剖面`。
- 资料类型词：`wiki`、`concept art`、`artbook`、`reference sheet`、`model sheet`、`walkthrough`、`reconstruction`、`data sheet`。
- **每次搜索的目标是补一个证据空洞**（例如"X 与 Y 的衔接关系"），不是泛搜"好看图"。

### 2.3 站点内检索

- MediaWiki 系：`insource:"<原文片段>"`、`intitle:<词>`、`incategory:<分类>`、`Special:Search` + 命名空间过滤；**分类页是成组取图最快的入口**。
- 论坛类：站内搜索 + 时间过滤（只取版本有效期内的帖子）；帖内楼层常含**多角度实拍**，比首楼更有价值。
- 代码/数据托管：搜生成器、数据集、参数表（常能直接拿到结构化数据，比图更可靠）。
- 开放数据：`<地区> open data`、`building footprints`、`DEM download`、`elevation contour`、`CC0 3D model`。

### 2.4 反查（以图搜图）

用图搜图找原始出处，顺序：反向图片搜索（多引擎交叉）→ 原始发布页 → 官方来源。反查结果要记录"我通过哪张图找到哪个源"，否则无法区分原图与转载。

## 2.5 **同类复刻作品与结构化素材库检索（开工前的必做动作）**

> 这一节是**硬要求**：G1 建参考包时，先问"**别人做过没有**"，再问"我去哪里拍"。
> 理由有三：① 别人可能已经把形状问题回答了一遍；② 能提前发现"这个对象早有高质量扫描数据"，省掉一整轮抓图；
> ③ 反面同样重要——能找到**别人做错了的地方**，避免重蹈。

### 2.5.1 两条线，必须分开记

| 线 | 找什么 | 可用作什么 | **不可**用作什么 |
|---|---|---|---|
| **A 同类复刻作品** | 其他游戏/Mod/体素/Minecraft/同人重建 | 对照参考：别人怎么读这个对象的体量与层叠关系；可作为"读法分歧"的证据 | **不得当几何/尺寸依据**：它们是二手创作，其本身可能就错；引用时必须标为对照而非证据 |
| **B 结构化素材库** | 3D 模型站（专业扫描）、开放图库、官方机构数据、地图 | 形状、比例、立面细节、足迹与方位（按 `01` 分级） | 商用许可未经核实的不得进交付物 |

### 2.5.2 实测可用的端点（2026-09-23；换环境需重测）

| 端点 | 检索方式 | 能拿到什么 |
|---|---|---|
| **Sketchfab** | `GET https://api.sketchfab.com/v3/search?type=models&q=<词>&count=N` | 模型名 / `faceCount` / `isDownloadable` / `license.label` / `user.displayName` / `viewerUrl`；专业扫描机构的账号（如 CyArk 一类）是最高价值线索 |
| **Wikimedia Commons** | `action=query&list=search&srnamespace=6` 搜文件；`list=categorymembers` 搜**分类树** | 开放许可照片（含超高分细节图）；更重要的是**分类常按对象部件分组**（见 §2.5.3） |
| 官方/机构站点 | 直取项目页 | 事实、历史、尺寸口径；页可能重排 → 404 要记入零结果 |
| **开放地图 / 场地底图** | OSM 系（`osmnx` + `geopandas`）拉路网与建筑足迹 | 可导出 SVG / GeoPackage / **DXF**（供 CAD/Rhino 用）；平面规则可靠，**高度/层数不可靠**；依赖清单见 `23` §5 |
| 开放地图/DEM 门户 | 见 §1 地图类 | 平面足迹、高程（**俯视原理上给不出层数**） |

**实测失败/不可用的通道**（记录以免重复尝试）：Brave HTML 检索连续请求返回 **429**；Bing HTML 返回**混淆跳转链**且结果与查询无关；Planet Minecraft **403**；Openverse `api/v1/images` 返回非 JSON。

### 2.5.3 关键技巧：用**分类树**成组取图（比逐张搜有用得多）

开放图库的分类往往已经把对象**按部件/视角**分好。先取分类树再取子类，比一个个关键词搜高效，而且不容易漏。
例（开放图库系的典型形态）：一个纪念性雕塑条目下会分出**按人物/按部位**的子分类、
气拍类、地图类、远景类、以及**原始模型/实物复制品**类。

**规范**：对"由多个可独立观察的子对象组成"的对象（群像、多塔、多舰、聚落），
参考包**按子对象建目录**，每个子对象先从它自己的子分类取一整套，而不是全局平均搜。

### 2.5.4 查询词组合（中英双写，写在取数台账里）

```text
<对象名 EN> + {minecraft, voxel, 3d model, 3d scan, photogrammetry, game map, build}
<对象名 中文> + {我的世界, 体素, 3D 模型, 建模, 游戏地图}
<对象名> + {stl, obj, glb, photogrammetry, mesh, point cloud}
<部件名> + {statue, relief, bust, model, replica}
```

### 2.5.5 纪律

1. **两条线的产物分开归档**：A 类进"对照"目录，B 类进"证据"目录；不得混放（与 `01` 的来源分级配合）。
2. **扫描类模型的等级不等于可商用**：可看 ≠ 可下载 ≠ 可重用；`isDownloadable=false` 只能取观感/截图作对照，
   且必须记下许可字段原值。
3. **零结果也要登记**（与 `11` 一致）："查过同类复刻，无可用结果"本身是一条结论，写清用了哪些词、扫了哪些站。
4. **不得把同类复刻当自己的量测来源**；若确实用了它的某个尺寸，必须回到 A/B 级一手源交叉验证。

## 3. 批量抓取与合规

**前置**：读目标站 `robots.txt` 与使用条款；确认该站是否允许自动化访问与再使用。

规则：

1. **限速与串行**：单域并发 1–2，请求间加延迟；遇到 429/403 退避重试，不要换 IP 绕过。
2. **保原始字节**：不重编码、不二次压缩、不裁掉元数据；保存 HTTP 头与来源 URL。
3. **不绕过访问控制**：登录墙、付费墙、验证码一律不碰；取不到就登记为缺口。
4. **可复现**：把搜索词、筛选条件、页码序列、抓取时间写进抓取日志，使他人能重跑同一批次。
5. **增量清单**：每批产出与 `07` §5 清单脚本兼容的 JSON（文件名 + 字节数 + 校验值），不要只在对话里报数量。
6. **命名**：进 `01_raw/`，用 `source_id` + 日期，禁止 `截图1`/`final` 这类名称（见 01 §6）。
7. 不抓取个人信息；不把抓取结果直接当硬锚点（硬锚点必须过 01 §7 的标定）。

## 4. 截图与捕获方法

### 4.1 网页 / 地图 / wiki

- **固定视口**：宽高、设备像素比、缩放级别写进日志；同一对象的多张截图必须同视口、同缩放。
- **干净画面**：关动画、关广告与推荐浮层、隐藏工具栏与图例；地图页要去掉"标注/卫星/地形"之外的 UI（UI 覆盖会污染颜色采样与轮廓判读）。
- **等加载完成**：瓦片是异步加载的，必须等瓦片请求结束再截，否则会出现空块。
- **超长页面**：优先全页截图；必须拼接时用固定重叠率（建议 15%–20%）并记录重叠参数，便于复核。
- **地图瓦片拼接**：保留每块瓦片的**行列号与原始尺寸**，先记录再拼接；拼完登记 seam、缩放级别与裁切边界（拼接本身会引入缝）。
- **地理配准**：取至少 3 个已知坐标点求变换（仿射即可起步），记录残差；配准前不要把图当平面图使用。
- **元数据**：记录页面上可见的版本号、更新时间、比例尺与图例，它们是 01 的"版本/口径"字段来源。

### 4.2 游戏 / 引擎内

- 机位与相机参数固定并登记**同一 8 个字段**（位置/朝向/FOV 或正交尺寸/分辨率/clipping/时间/灯光组/参考图版本）——与 `06` §7 一致。
- **关 HUD 与 UI**；固定时间、天气、光照；关景深与泛光。
- **测量优先用正交模式**；透视图只用于评估与语义判读，不用于尺寸推导（01 §7）。
- 录制视频抽帧时：固定帧率、记录时间码；避开运动模糊与转场帧。
- 3D 视图截图至少给**正交三视 + 一个四分之三视角**，并同时导出包围盒与单位。

### 4.3 输出分层（与 01 §6 一致）

```text
01_raw/     原始下载或截图，只读不覆盖
02_norm/    统一尺寸/裁切/纠偏后的标准副本
03_annot/   标注、测量、叠加（不得成为唯一证据）
```

## 5. 污染与陷阱（每条都会毁掉一次复刻）

| 陷阱 | 后果 | 处置 |
|---|---|---|
| UI/HUD/准星/地图标注覆盖 | 颜色与轮廓被污染 | 判为 UI 污染旗标；不用于颜色采样与轮廓测量 |
| 后处理（景深/泛光/色调/天气） | 材质与光照判断失真 | 判为后处理污染旗标；材质结论必须另找无后处理来源 |
| 版本差异（更新、改版、同人重建版本） | 拿旧版证据验新版 | 文件名与索引带日期与版本；只取版本有效期内的帖子 |
| AI 生成图 / 同人二次创作 | 结构被凭空发明 | 只能 D 级、只作气氛；不得回推结构 |
| 缩略图当原图 | 无法标定、无法放大 | 必须保存原图与原图 URL；缩略图另存并标注 |
| 按颜色阈值定位（如"按红色像素找点"） | 被同色构件干扰，误判为通用算法 | 颜色只用于人工排查，不得当定位算法（项目实测教训，通用适用） |
| 拼接不记 seam 与重叠率 | 后续无法复核几何 | 记录行列号、缩放级别、重叠率与 seam |
| 把透视截图当正交图 | 尺寸推导系统性偏差 | 正交投影必须来自最终运行结果或正交相机 |

## 7. 本文件的通用性边界

- 站点清单是**示例与分类**，不是强制路径；平台可用性、条款与检索语法会变，使用前复核。
- 本文件不提供任何绕过访问控制、限速或版权限制的方法；合规责任在使用者。
- 不包含任何项目的私有素材库地址或内部检索链（按项目文档接入）。
- 本文件不定义证据等级与验收门禁；等级判定以 `01` 为准，门禁以 `04` 为准。
