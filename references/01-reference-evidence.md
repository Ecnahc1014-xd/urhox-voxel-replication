# 参考资料检索、来源分级、标定、冲突登记与归档

| 字段 | 规定 |
|---|---|
| 适用阶段 | G1 参考资料包与来源分级（上承 G0 任务与证据边界，下接 G2 工程制图） |
| 适用对象 | 任意复刻对象：城市/聚落、街区/场地、单体建筑、室内、自然景观、道具/载具/装置、混合场景 |
| 对象类型分派 | 证据源与覆盖维度按对象类型选择，见 `references/08-subject-classes-and-scales.md`；本文件不在通用章节预设任何一类对象 |
| 主责任 | 资料取证负责人 |
| 共同签核 | 测绘、技术美术、QA、交付负责人 |
| 基线原则 | 原始不覆盖、来源可追溯、用途有限定、冲突不静默、结论可回放 |
| 引擎前提 | 采集字段与哈希流程引擎中立；涉及引擎资源路径的条目按第 14 节前提声明 |

本文件只说明“怎样把散乱素材变成可进入工程图与验收的证据”。参考包不是灵感收藏夹，也不是报告素材库；它的产出必须能被 G2 的注册链直接消费。

## 1. 目标与产出

- 动作：为每个对象或区域建立一个 `reference_pack_id`，产出一份索引、一份冲突表、一份检索日志和一套分层保存的图片/视频。
- 动作：每份证据写清“证明什么、不能证明什么、是否经过裁切或标定、能进入哪张工程图”。
- 验收：任取一条结论，都能沿“来源 → 主张 → 图物 → 验证”链回到原文件；回不去的结论只标探索性，不得冻结硬锚点。
- 动作：**自造的可视化不是参考**。我方渲染、我方测量可视化、热图/叠加图一类**派生分析图**一律标 `SELF_MADE`，只允许存放于 `04_annotations/`，**禁止进入参考包**（它是我方的读数，不是证据）；也**禁止占对照板的“参考”位**——对照板上可以出现我方当前状态，但那一半必须显式标 `SELF`，与“参考”半边在版面上分开。
- 动作：同一素材的**转载/裁切/改名**不算多条独立来源（归一键与动作见 §6.1）。
- 动作：搜索缩略图、无来源转载、AI 生成或补全图、只展示气氛的概念图、带强透视且无尺度锚点的单帧、版本未确认的社区重建图，一律登记并降级，不得直接当作工程事实，也不因降级而删除。

## 2. 搜索任务定义

- 动作：先写“证据问题”，再写关键词。证据问题必须指向一个空洞，例如“<子对象 A> 与 <关键构件 B> 的开口关系”，而不是“<对象> 好看的图”。
- 动作：先按 `references/08` 第 2 节确定对象类型，再按类型选择证据源；证据源与对象类型错配（例如用照片证明地形高程、用氛围图证明室内房间）时，该轮证据作废重建。
- 取数手段（去哪找、怎么搜、怎么批量抓、怎么截图与拼接）见 `references/09-reference-sourcing-and-capture.md`；**已实测跑通的站点、端点与抓取参数**见 `references/09a-source-catalog.md`；本文件只管判定标准，不重复站点与工具细节。
- 动作：关键词使用固定四元组，缺任一维度会系统性漏掉部分来源：

```text
对象 × 视角/结构 × 资料类型 × 版本/时间
```

- 动作：每次检索登记 query、检索日期、使用平台、筛选条件、命中条数、最终采用来源与采用原因，并同时使用当地语言、英文、对象在源作品中的正式名称与社区常用名。
- 验收：他人仅凭检索日志能复现“为什么找到这张图”；不允许只留“已搜过”这类不可复现的记录。
- 动作：视角/结构词与资料词按对象类型轮换，不把同一组词套到所有对象上。

| 对象类型（见 `references/08`） | 首选证据源 | 视角/结构词 | 资料类型词 |
|---|---|---|---|
| 城市 / 聚落 | 官方地图与总平面、航拍 | top view、aerial、map、boundary | official map、interactive map、reconstruction、walkthrough |
| 街区 / 场地 | 场地平面图、卫星影像、场地照片 | site plan、axis、paving、boundary | survey、campus map、reconstruction |
| 单体建筑 | 三视图、立面照、尺寸标注 | facade、floor plan、section、roof | architecture analysis、reference、comparison |
| 室内 | 房型图、剖切图、室内照片 | floor plan、section、ceiling height、door | interior reference、walkthrough |
| 自然景观 | 等高线/DEM、卫星影像、水位与季节数据 | contour、elevation profile、shoreline、water level | DEM、topographic map、hydrology |
| 道具 / 载具 / 装置 | 多角度照片、三视图、部件清单 | front、side、top、detail、part | parts list、manual、reference |
| 混合场景 | 各子类分别采集并共享一套注册 | 按子类各取上述词 | 按子类各取上述词 |

## 3. 来源等级与允许用途

| 等级 | 可信度来源 | 允许支持 | 不允许单独支持 |
|---|---|---|---|
| A | 官方地图、游戏内固定机位、官方页面、可验证原始数据 | 命名、方位、轮廓、版本事实 | 未经标定的精确尺寸、室内结构 |
| B | 多角度实机截图、连续视频、建筑考据、同源高质量重建 | 空间关系、立面构件、剪影、材质语法 | 把单帧透视当正交工程图 |
| C | 玩家地图、社区重建、攻略标注、论坛图 | 缺口补全、候选假设、语义线索 | 单独冻结硬锚点与整体比例 |
| D | 缩略图、无来源转载、概念氛围图、AI 图 | 配色与氛围候选、继续检索的种子 | 任何注册、尺寸、语义位置或事实结论 |

- 动作：来源等级与实际用途分开记录。A 级不等于无误差：官方世界地图可能有投影变形，固定截图可能有透视，版本更新可能改变对象本身。
- 验收：索引中每条记录都能回答“这条证据被允许支持哪一类结论”。

### 3.1 虚构/风格化对象的证据规则

对象可以是虚构或风格化的（游戏内城市、幻想建筑、概念载具、艺术化地形）。此时证据标准不变，只改变“忠实”的指向：

- 动作：**忠实于指定设定稿**。以项目或用户指定的设定稿、概念图、官方宣传素材为唯一权威来源，在索引中把该来源标为 `DESIGN_CANON` 并在 `semantic_role` 中写明它定义哪一部分（体量、比例、配色、构件语法）。
- 动作：**不得伪造官方数据**。虚构对象没有真实测绘值：禁止用真实世界地名、真实测绘数值或“官方尺寸”措辞填充 `known_scale_or_anchor`，禁止把推测尺寸写成 A 级来源支持的结论。
- 动作：来源分级仍适用（第 3 节）。设定稿可判 A 级（若确为指定权威），同人重建、截图、氛围图按 B/C/D 处理；A 级设定稿只支持“设定如此”，不支持“结构可行”“尺寸可施工”这类推断。
- 动作：风格化比例（夸张头身比、非物理悬挑、压缩进深）是**设计事实**，登记为 `STYLIZED_PROPORTION` 旗标后允许照抄，不得以“不符合真实建筑惯例”为由擅自修正。
- 动作：设定稿之间的冲突按第 9 节冲突表处理，候选保留；不允许用“平均值”或“合理化”抹平风格差异。
- 动作：设定稿只有单一视角时，未观测面的形状标 `UNVERIFIED` 或 `DESIGN_INTERPOLATED`，并在模型中给出可替换的简化体量，不得声称与设定一致。
- 验收：任取一条虚构对象的结论，都能回答“它由哪份设定稿的哪个部位支持”；无设定依据的补全部分必须显式标为设计推断。

### 3.2 等级 ↔ 能力清单（判级按“能力”，不按“通道/文件名”）

同一张图，从不同通道进来会被判出不同的等级——这是错的。判级依据只有一个：**这张图在本对象上能支持哪类结论**（第 3 节表中的“允许支持”列）。下表把该列翻成可对照的清单；判级理由必须引用**本图在本对象上的可用轴**（例：`side 实机截图 → 可用轴 = 竖向(H) + 进深(D) → B 级，支持剪影/层高比`）。

| 等级 | 能支持（能力） | 不能单独支持 | 典型来源（仅示例，不用于判级） |
|---|---|---|---|
| A | 命名、方位、轮廓、版本事实 | 未经标定的精确尺寸、室内结构 | 官方地图、游戏内固定机位、官方页面、可验证原始数据 |
| B | **剪影、空间关系、立面构件、材质语法**、层叠顺序 | 把单帧透视当正交工程图；未经标定的绝对米制尺寸 | **多角度实机截图**、连续视频、建筑考据、同源高质量重建 |
| C | 缺口补全、候选假设、语义线索 | 单独冻结硬锚点与整体比例 | 玩家地图、社区重建、攻略标注、论坛图 |
| D | 配色与氛围候选、继续检索的种子 | 任何注册、尺寸、语义位置或事实结论 | 缩略图、无来源转载、概念氛围图、AI 图 |

- 动作（禁止项）：**按通道名 / 文件名判级**。只写“第三方截图”“wiki 图”“论坛图”不算判级理由，必须回到“它在哪个轴上支持哪类结论”重判。
- 动作：同一图承担多个用途时，**逐用途登记**它在该用途上的能力（一张图可以在“剪影”用途上是 B，在“层高”用途上是 C）。
- 验收：任取一条等级，都能回答“这张图在本对象的哪个轴上支持哪类结论”；回答不了的按 `UNVERIFIED` 处理。
- 实证（负样本）：某路把 8 张**多角度实机截图**按“第三方截图”通道一律记 C 级“一切几何”，结果它们从未进入形制对照——而按第 3 节定义它们是 B 级，本就支持剪影与立面构件；同期另一张带注记俯视图被按文件名记成 `iso`（`19` §2 禁 iso 作量测），判定同样错。

## 4. 参考包目录结构（通用形式）

```text
REF_<project>_<object>_<pack_version>/
  00_manifest/
    reference-index.csv
    source-conflicts.csv
    query-log.md
    evidence_manifest.json（由 `07` §5 清单脚本生成；旧版 `SHA256SUMS` 已废除）
  01_raw/               原始下载或截图，只读不覆盖
  02_normalized/        方向、格式、颜色空间统一后的派生图
  03_crops/             对象裁切，保留原图坐标与边界
  04_annotations/       标注、网格、锚点、视线、问题号
  05_contact-sheets/    按对象/视角/版本生成的索引板
  06_exports/           已确认进入工程图与资产表的证据
```

- 动作：`<project>`、`<object>`、`<pack_version>` 使用项目参数表规定的标识，目录名不带空格与中文标点。
- 动作：原图、标准化图、裁切图、标注图分层保存；任何标注不得覆盖唯一原图；外部链接不作为唯一交付，必须保存本地副本或可验证的来源快照。
- 验收：删除 `02`–`06` 任一目录不影响 `01_raw` 的可读性；任一派生文件都能反查回它的原图。

## 5. 索引字段与命名

`reference-index.csv` 至少包含：

```text
reference_pack_id / source_id / title / object / semantic_role / source_grade
origin_url_or_archive_path / captured_at / source_version / patch
original_filename / local_path / sha256
view_type / view_direction / camera_hint / known_scale_or_anchor / coordinate_hint
supports / limitations / derived_from / crop_rect / annotation_version
authority_score / coverage_score / calibration_score / clarity_score / quality_flags
confidence / reviewer / status
```

文件命名统一为 `REF_<pack>_<source_id>_<view>_<grade>_<YYYYMMDD>[_rNN]`。

- 动作：同一来源的原图、裁切图、标注图共用同一 `source_id`，用后缀区分派生层；禁止“截图1”“好图”“final”这类名称。
- 验收：对目录做一次名称扫描，文件名缺失 pack、source_id、grade、日期任一字段即为不合格。

## 6. 原图保全与派生链

1. 动作：下载或截取后立即复制进 `01_raw/`，计算 SHA-256，保留原始分辨率、原文件名、时间信息与来源地址。
2. 动作：原图只读，不涂画、不压缩覆盖、不因重命名而丢失来源。
3. 动作：标准化只做不改变几何含义的操作（方向统一、颜色空间标记、无损格式转换、去掉浏览器边框与重复 UI 说明）。
4. 动作：裁切、透视矫正、拼接、拉伸、颜色调整必须新建派生文件并记录参数；标注使用独立图层或透明叠加，注明北向、锚点、主轴、剖切线、视线、遮挡、问题号、置信度与来源号。
5. 动作：无法确认来源或版本的图标记 `UNVERIFIED`，不得在后续引用中悄悄升格。
6. 验收：`01_raw/` 内文件的哈希与 `evidence_manifest.json` 的 `files[].sha256` 一致（清单由 `07` §5 脚本生成，不再使用独立的 `SHA256SUMS`）；任取一张标注图，都能找到对应无标注原图。

### 6.1 语义去重（同素材的转载 / 裁切 / 改名）

字节级去重（sha256）只能拦住“同一文件”，拦不住“同一素材的不同文件”。另立**语义归一键**：

```text
归一键 = sha256(原图) + 图注中的对象名 + 作者 / 日期
```

- 动作：命中同一归一键的图**算一条证据**：索引里填 `duplicate_group`，非保留者标 `DUPLICATE_OF <source_id>`；`DUPLICATE_OF` 的语义从“字节重复”扩展为**语义重复**（转载、裁切、改名、重压缩均适用）。
- 动作：命中语义重复时**撤销被重复计入的证据数**：冲突表、三角测证与覆盖矩阵里的计数同步减一，并在 `00_manifest/query-log.md` 记一行（谁、何时、哪两条合并、影响哪条结论）。
- 动作：**同名不同物也要能拆开**：图注对象名不同而 sha256 相同时标 `CAPTION_CONFLICT` 并人工确认，禁止按文件名自动合并。
- 验收：参考包内不存在两张 `duplicate_group` 相同的图被当作两条独立来源；任一 `duplicate_group` 只能贡献 1 条证据。
- 实证（负样本）：某包把**同一张 Commons 照片**（图注“外滩中国通商银行大楼”= 6 号）登记为 `BUND-S15`、`BUND-S30` 两条来源，去支撑“9 号”结论 → 证据数虚增 + r77 重复错建；同包“字节重复已删、语义重复无闸”正说明去重不能只做到 sha256 一层。

## 7. 视角、标定与可测性

| 视角 | 可主要支持 | 必须声明的限制 |
|---|---|---|
| 正交/平面或总平面 | 方位、轮廓、相对位置、空间关系 | 投影方式、比例、旋转、裁切边界 |
| 航拍/高位斜视 | 地表轮廓、连续关系、天际线、区块边界 | 透视、遮挡、镜头高度未知 |
| 正面/侧面立面 | 宽高比、屋顶、塔、桅杆、材质带 | 视点偏角、焦距、遮挡 |
| 连续视频帧 | 路线、入口、遮挡变化、玩家视线 | 帧时间、镜头移动、动态对象 |
| 近景材质 | 色彩分区、粗糙度语法、构件细节 | 光照、后处理、天气对颜色的污染 |

- 动作：视角组合按对象类型取用：城市/街区类需平面加立面与路线，单体建筑类需三视图或立面加尺寸标注，室内需房型图加剖切，自然景观需等高线、高程剖面与水位，道具类需多角度加部件清单；缺少该类型必需视角时结论止于候选。
- 动作：需要量尺寸时至少标定一个已知尺度（门宽、桥宽、角色身高、标准台阶等重复尺度），关键比例至少用三个分散锚点交叉验证；无法标定时只记录相对关系，不输出绝对米制坐标。
- 动作：平面参考进入工程图前完成“裁切边界记录 → 北向/轴向确认 → 锚点标注 → 比例或相对尺度声明 → 与第二来源交叉核对”。
- 动作：所有正交化结果标记 `ORTHO_APPROX` 或 `ORTHO_VERIFIED`；前者只用于视觉叠加与候选布局，后者必须有尺度锚点、变换参数与独立来源支持。
- 验收：每张被用于测量的图都能回答“标定了哪个尺度、误差范围是多少”；缺失时写 `UNVERIFIED`，不得给出看似精确的米制值。
- 动作（禁止项）：只凭单张透视图推导整体绝对米制坐标；无记录地拉伸、压缩、旋转原图以求轮廓重合；把透视校正后的派生图当原图；用 AI 补全或锐化后的边界直接测量。
- 动作：**锚点量测只允许来自含对象本体的图**（判据见 `19` H6）：比例锚、配色锚、剪影锚的母图必须能看到本体；“局部特写”须显式声明并给位置框。用不含本体的画面（车内、遮挡后、只拍到地面）做锚，等于给模型定了一个无法核对的标尺。

## 8. 证据板

每个关键对象至少形成一张证据板，内容固定为：原始参考（含来源号）、标准化或裁切结果、锚点/方向/视线/结构标注、与其他来源的对照缩略图、支持结论与限制条件与置信度、进入哪张工程图或哪个资产字段。

- 动作：每个对象类型使用一组固定板号，板号在项目参数表中登记；**板号规则的唯一出处是本文件末尾「后裁定细则」第 4 条**（本节不复制正文）。
- 验收：每块证据板都能被索引中的 `source_id` 直接定位；不出现“板上有图、索引里没有”。

## 9. 三角测证与冲突登记

- 动作：关键结论采用三角测证，至少两种不同类型来源支持；只有单一来源时标 `LOW_CONFIDENCE`，不得冻结为硬锚点。
- 动作：先识别稳定锚点（主入口、主轴交点、主体轮廓拐点、基准面或水位、大型识别性构件等），再由锚点传播推导次级语义位置（POI 或关键构件）；不从软装饰反推主坐标。
- 动作：显式记录负证据，例如“航拍证明轮廓，不证明室内房间”。
- 动作：来源冲突进入 `source-conflicts.csv`：

```text
conflict_id / claim / object / candidate_a / candidate_b / source_a / source_b / grades
difference / decision / decision_reason / impact_on_drawings / reviewer / status
```

- 动作：处理顺序为“确认版本与视角 → 判断是否为投影/透视差异 → 引入第三来源交叉 → 仍无法决定时保留两个候选并把影响传递到工程图与模型”。
- 验收：冲突表条数与索引中标记冲突的记录数一致；出现“平均值抹平差异”或“只留一个候选、删掉另一个”的写法即判为不合格。

## 10. 质量评分

在 `reference-index.csv` 中增加四个独立评分，避免“来源等级高”掩盖“不可测”：

```text
authority_score 来源可靠性：0-3         coverage_score 对目标证据问题的直接覆盖：0-3
calibration_score 尺度/方向/版本可标定性：0-3   clarity_score 清晰度、遮挡、压缩与后处理质量：0-3
```

含义：0 不能支持该用途；1 只能作候选或气氛；2 可以交叉使用；3 可以直接进入对应工程图或视觉回归。

- 动作：`authority_score=3` 但 `calibration_score<2` 的图，只允许支持命名、方位或构件存在性。
- 动作：评分阈值由项目参数表给出；未给出时写 `UNVERIFIED`，不得自造“总分下限”。
- 验收：抽查三张进入基线的图，其四项分数与 `supports`/`limitations` 描述不矛盾。

## 11. 污染旗标与去重

参考图索引增加质量旗标，至少包括：

```text
UI_CONTAMINATED 有 UI/文字/准星/地图覆盖       POSTFX_CONTAMINATED 景深/色调/泛光或天气后处理
LIGHT_CONTAMINATED 光照导致颜色不能代表材质     OCCLUDED 关键构件被角色/树/特效/建筑遮挡
PERSPECTIVE_STRONG 透视强，不能当正交几何       COMPRESSED 分辨率低、重压缩或缩略图
DYNAMIC_STATE 门/旗/船/碎块等处于动态状态       VERSION_UNCERTAIN 版本不明
```

- 动作：旗标不是删除理由，而是使用边界。带 UI 的图可以支持方向与语义位置，带后处理的图可以支持氛围，两者都不能用于绝对尺寸测量或纯材质采样。
- 动作：虚构/风格化对象另用两个旗标：`STYLIZED_PROPORTION`（风格化比例）与 `DESIGN_INTERPOLATED`（无设定依据的补全），用法与上面相同：登记后仍可使用，但必须在 `limitations` 中写明使用边界（见第 3.1 节）。
- 动作：按来源家族归组后再判断重复，保留优先级为“版本明确且来源可追溯 → 原始分辨率高、压缩少 → 视角更接近目标、遮挡更少 → 结构与材质信息更完整”。
- 动作：用感知哈希辅助发现近重复，但不按像素相似度自动删除（同一画面的不同版本可能记录重要状态变化）；被淘汰的图仍留在 `01_raw/`，在索引中标记 `DUPLICATE_OF` 或 `LOWER_QUALITY_OF` 并写明保留者。
- 验收：带旗标的图在 `limitations` 中都有对应使用禁令；索引中不存在“被删除的唯一原图”。

## 12. 视频与运行时截图采集字段

用于路线、遮挡与运行时对齐的截图或视频必须记录：

```text
capture_id / source_id / scene / build_or_patch / capture_date / camera_position_or_route
resolution / aspect_ratio / FOV_or_ortho / time_of_day / weather / light_state
player_state / dynamic_state / frame_number_or_timestamp
```

- 动作：连续视频先建时间码索引再截帧；移动镜头用于判断遮挡先后，不用于绝对长度。
- 动作：若截图来自运行时烘焙或 PIE 会话，同时保存场景、机位与运行日志。
- 验收：不允许把编辑器临时状态或未归档的运行时画面当成参考事实；缺任一必填字段的采集件记为 `INCOMPLETE`，不得进入参考包正式状态机。

## 13. 材质、颜色与引擎资源检索

- 动作：材质参考把“物体颜色”与“光照结果”分开记录：对象、表面朝向、时间与天气、光源颜色、是否带后处理、采样位置。
- 动作：颜色样本至少分为基础色候选、阴影/环境色、边缘/高光、材质语义四类；不从高光、阴影或 UI 叠加区域取色。
- 动作：需要项目内材质、模型、预制体或纹理时，按“项目 `assets/` 与已有索引 → 项目实测的资源库解析链或快照 → 编辑器素材查询入口 → 公开来源（记录授权、原格式与转换步骤）”的顺序检索；不凭记忆编造 UUID 或 Technique 路径。
- 动作：资源命中不等于可用资产，还要核对 UUID/URI、版本、坐标、单位、包围盒、贴图依赖、透明度与法线、体素化方式和目标尺寸；找不到完全匹配时优先使用项目已有材质变体或明确的 `PBRNoTexture` 参数组合，把替代关系写入资产表，不为视觉相似临时改动全局调色板。
- 验收：每个外部素材都记录了检索词、资源名、版本、缩略图、原始文件、转换工具、目标体素尺寸与验收状态。

## 14. OCR 与 AI 辅助边界

- 动作：OCR、颜色阈值、目标检测、感知哈希、AI 图像分析只生成候选，不得自动写入硬锚点或正式尺寸。
- 动作：自动结果必须保存工具与模型版本、输入 `source_id`、输出候选、人工复核人与修订原因。
- 动作：逐条排查已知风险：颜色阈值把屋顶当作点位标记、OCR 把 UI 文字当成地名、分割把阴影当成边界、AI 补全改变原始轮廓。
- 验收：每条自动提取结论都有原图回查记录和第二来源；缺任一项时置信度降级并写入 `limitations`。

## 15. 来源 → 主张 → 图物 → 验证 追溯链

关键结论建立如下链路：

```text
source_id → claim_id → drawing_id / poi_id → asset_id → verification_id
```

- 动作：`claim_id` 是冲突表、工程图、资产表与验收记录共用的键；新增或修订主张时同步更新引用它的位置。
- 动作：无法沿链路回溯的结论只标探索性，不得成为冻结注册或正式资产验收依据。
- 验收：抽取三条 `claim_id`，能在索引、工程图与验收记录中闭合；断链即判该主张未就绪。

## 16. 覆盖矩阵（替代“图片数量”考核）

| 对象 | 平面/方位 | 高程/剖面 | 正/侧立面 | 语义/路线 | 材质/构件 | 最低要求 |
|---|---|---|---|---|---|---|
| <主体 A> | A/B | B | B | A/B | C | 项目参数表指定 |
| <主体 B> | A/B | B | B | A/B | B/C | 平面 + 路线 + 中景 |
| <关键构件 C> | A/B | B | A/B | B | B | 主立面与相邻关系 |
| <通道或接入节点> | A/B | B | B | A/B | B/C | 开口关系与作业道具 |

- 动作：覆盖维度按对象类型取用：单体建筑类以三视图与关键尺寸链替代平面/路网维度，自然景观类以等高线与水位替代立面维度，室内以房型图与剖面替代平面与立面维度；被替代的格子改填对应证据源，不填 `MISSING`，并在参数表中登记替代关系。

- 动作：空洞显式记为 `MISSING`，不能用相邻对象的图片默认已覆盖。
- 动作：核心硬锚点至少有一张空间/平面证据和一张视觉/立面证据；只有近景材质图而没有空间关系时，不得进入主体基线。
- 验收：覆盖矩阵中非 `MISSING` 的格子都能指向具体 `source_id`，且等级不超出第 3 节允许范围。

## 17. 参考包门禁与状态

> **本节只负责“参考包整体状态与签核”；“一张图能不能进包”的判据唯一出处是 `19`（H1–H6），本节不复制其正文。**

| 门禁 | 检查 | 通过条件 |
|---|---|---|
| REF-F0 来源 | URL/快照、日期、版本、hash、原文件 | 原始证据可追溯、不空、不覆盖 |
| REF-F1 用途 | **判据见 `19` H1/H2/H5/H6**（本节不复制） | 一张图不承担超出能力范围的结论，且身份与在场性已核 |
| REF-F2 标定 | **判据见 `19` H2 与 `02` 注册链**（本节不复制） | 可测与不可测内容明确 |
| REF-F3 交叉 | 第二来源、冲突表、置信度 | 关键结论有交叉或明确降级 |
| REF-F4 派生 | 原图/裁切/标注链、文件命名 | 任一派生图可追溯回原图 |
| REF-F5 交付 | 证据板、索引、manifest、签核 | 可进入工程图或被明确排除 |

参考包状态只允许：`COLLECTING`、`NORMALIZED`、`CROSS_CHECKED`、`PASS`、`BLOCKED`、`SUPERSEDED`。只有 `PASS` 的证据才能进入正式基线。

- 动作：出现来源不明、版本混用、裁切覆盖原图、透视图被当成正交图、AI 图被当作事实、或冲突未记录时，状态置为 `BLOCKED`。
- 验收：状态变更在 `00_manifest/query-log.md` 或变更记录中留下原因与 reviewer。

## 18. 归档命名、审查与签核

归档命名统一为 `REF_<project>_<object>_<pack_version>_<YYYYMMDD>`。

- 动作：每次更新提升 `pack_version`，保留旧包与变更摘要；不做覆盖式“更新素材库”。
- 动作：参考包审查会至少输出：覆盖矩阵中未满足的格子、A/B 来源之间的冲突与选择理由、需要进入工程图的 `claim_id`、被降级为候选或气氛的图片、下一轮检索的唯一缺口、reviewer 与日期。
- 动作：审查后若新增来源改变了轮廓、主轴、关键构件 footprint 或版本事实，必须触发本 Skill 的变更影响流程，不能只改图片文件名。
- 动作：交接前逐条核对清单：

```text
[ ] 每项主参考都有来源、日期、版本、原文件与 SHA-256
[ ] 每个硬锚点至少有一张空间/平面证据和一张视觉/立面证据（维度按对象类型取用）
[ ] 每张图都写明支持项、限制项、视角与标定状态；原图/标准化/裁切/标注分层保存
[ ] 冲突候选、选择原因与影响范围已进入冲突表；语义位置表（POI 或关键构件表）无无来源坐标
[ ] 高程估计与官方事实分开标注；证据板、索引、manifest 与签核状态可一并归档
```

## 20. 本文件的通用性边界

- 本文件只描述分析与归档流程，**不含任何具体项目、对象或数值**；数值必须来自项目参数表或案例，缺失即 `UNVERIFIED`，跨项目复用前重新测量。
- 第 3、10 节的等级与评分是**相对判据**，不是精度承诺（官方来源也可能带投影误差）；第 4、18 节的目录与命名是模板——项目已有归档约定时按项目约定执行，只要求“分层、可追溯、版本提升、不覆盖原图”四条性质成立。
- 第 13 节的检索顺序依赖引擎与项目现状：换引擎或换资源库前必须先确认解析链与素材查询入口存在，否则不得沿用。
- 本文件不替代 G2 工程制图与 G5–G6 验收（参考包 `PASS` ≠ 几何/接地/碰撞/运行时正确）；也不预设对象类型——证据源、视角组合、覆盖矩阵与板号按 `references/08` 分派。
