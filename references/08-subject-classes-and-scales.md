# 对象类型、尺度等级与门禁裁剪

本文件是通用流程的**分派层**：先在这里确定“复刻的是什么、多大、要多少细节”，再决定 G0–G7 里哪些阶段必需、`references/04-verification.md` 的四张检查表里哪些项适用。裁剪规则见 SKILL.md 第 3 节（裁剪的是检查项，不是证据标准；裁剪必须留痕）。

## 1. 两个正交维度

- **对象类型（subject class）**：决定**证据类型与注册基准**——即“用什么资料证明它长得对、以什么为坐标基准”。
- **尺度等级（scale tier）**：决定**体素尺寸、细节预算与验收精度**——即“多细算够、多粗算错”。

两者必须同时填。只填“类型”会出现细节预算失控；只填“尺度”会出现证据类型错配（例如拿照片去复刻地形高程）。

## 2. 对象类型

| 类型 | 典型对象 | 证据优先 | 注册基准（主数据） | 建模顺序 | 验收重点 | 常见失效 |
|---|---|---|---|---|---|---|
| 城市 / 聚落 | 城市、城镇、村落、港区 | 官方地图与总平面、航拍、地标立面 | 路网与 POI 表 + 冻结注册变换 | 地形与边界 → 主路与地标 → 街区 → 装饰 → 动态 | 轮廓与路网重叠、地标足迹、接地、连通性 | 全局比例漂移、地标错位、装饰抢占净空 |
| 街区 / 场地 | 广场、园区、校园、庭院、码头 | 平面图、场地照片、卫星影像 | 场地边界与主要轴线 | 边界与地坪 → 主构筑物 → 铺装与植被 → 小品 | 边界闭合、地坪高差、通行净空 | 地坪不连续、边界破口 |
| 单体建筑 | 塔、教堂、民居、工厂、桥 | 三视图/立面照、尺寸标注、同类建筑参照 | 包围盒 + 基准面 + 关键尺寸锚点 | 体量与轮廓 → 主结构 → 立面构件 → 屋顶与装饰 | 剪影一致、层高与开洞比例、屋顶轮廓 | 层高失真、屋顶走形、开洞错位 |
| 室内 | 房间、厅堂、地牢、机舱 | 房型图、剖面、室内照片 | 房间原点 + 层高 + 门洞位置 | 地坪与墙体 → 门洞与楼梯 → 家具与陈设 | 净空、门洞通过性、比例压迫感 | 层高偏差、通道不可通过、家具穿插 |
| 自然景观 | 地形、山体、丘陵、水体、海岸、峡谷、植被群 | 等高线/DEM、卫星影像、水位与季节数据 | 地理配准后的等高线与水位基准 | 基准面与等高线放样 → 水系与岸线 → 坡面与岩体 → 植被群 | 高程分层、坡面连续、水位与岸线一致 | 阶梯化过重、水面穿透地形、坡面断裂 |
| 大型道具 / 载具 / 装置 | 船、车、飞行器、机械、雕塑、摊车 | 多角度照片、三视图、部件清单 | 主轴线 + 关键部件尺寸链 | 主轴线与主体量 → 主要部件 → 细部与索具 → 分件材质 | 剪影与比例、部件拓扑、重心与接地 | 部件比例失衡、索具/桅杆越界被裁 |
| 混合场景 | 上述多类的组合（如“带码头的城镇”） | 各子类证据分别采集 | 共享同一套注册变换，按子对象登记 | 按“大尺度到小尺度”顺序 | 跨子类接缝一致性 | 子对象各自维护缩放、接缝错位 |

选型规则：

1. 以**最小可辨识单元**定类型：若对象的核心可辨识度来自地形，就是自然景观；来自立面和屋顶，就是单体建筑；来自路网与地标排布，就是城市/聚落。
2. 混合场景必须**显式列出子对象及其类型**，并共享一套注册；不允许子对象各自维护缩放。
3. 分类不确定时先做一件低成本的事：把候选类型各写一句“用什么证据证明它像”，选证据可获取的那一类。
4. **（可选）** 想把“它是不是房子/山”变成可核对清单，见 `references/24-semantic-enhancement-optional.md` 的推荐必含项与关系检查；
   那是**可选层、不属四张表、不新增门禁**，未启用不影响本文件的类型与裁剪结论。

## 3. 尺度等级

| 等级 | 跨度（量级） | 建议体素尺寸（量级，需项目实测确认） | 细节预算重心 | 主要风险 |
|---|---|---|---|---|
| S1 微物件 | < 1 m | 0.5–5 cm | 单一构件的形与材质 | 体素数爆炸、材质噪声 |
| S2 单物件 / 房间 | 1–10 m | 2–20 cm | 主结构 + 少数识别性构件 | 细节过密导致全网格过重 |
| S3 建筑 / 小型场地 | 10–100 m | 0.2–1 m | 轮廓、层高、开洞、屋顶 | 轮廓失真比构件粗糙更致命 |
| S4 街区 / 景区 | 100 m–1 km | 0.5–2 m | 体量关系与地标剪影 | 装饰抢占净空、批次过多 |
| S5 城市 / 区域 | 1 km 以上 | 1–5 m | 拓扑正确、地标可辨识 | 指标漂移、生成时间与内存失控 |

上表体素尺寸是**量级参考**，不是默认值：必须以“最小可辨识构件”反推并写入参数表，且在 G0 冻结。

**粗尺度的显式例外（解决 S4/S5 与 1/3 规则互斥）**：S4–S5 的“最小可辨识构件”指**该尺度自己的可辨识构件**（例如街区轮廓、主轴线、关键体量的开洞节奏），默认**不承诺** S1–S3 级细节（窗棂、栓栏、单个道具）。因此：

- S4–S5：最小可辨识构件 = 该尺度下的识别性构件，其尺寸必须 ≥ 3 × 体素尺寸；S1–S3 级细节列入“不在本尺度承诺范围”。
- 需要在 S4–S5 场景里保留 S1–S3 级细节时，必须按第 3 节声明**跨尺度拼接**，并为该物体单独登记体素尺寸与可辨识性依据；不得用整场景的平均尺度冒充。
- S1–S3：仍按下面的 1/3 规则执行，不允许用本例外降低细节。

选择规则：

- **体素尺寸 ≤ 目标最小可辨识构件的 1/3**；做不到时只能显式降低细节目标，并登记该降级。「最小可辨识构件」的尺寸必须登记为参数表必填项（含剪影覆盖体素数复核，见 `03` 后裁定细则 1）；未登记即 UNVERIFIED，体素尺寸预算不得定案。
- 细节预算至少记录三项：总体素数上限、单对象体积数上限、动态体上限。
- 尺度等级跨级拼接（如 S5 城市里放 S1 道具）时，必须在参数表里显式允许该跨级，并说明该物体的可辨识性由什么保证。

## 3.1 单位方块与人物尺寸：两条强规则（跨引擎通用）

以下两条是**强规则**（登记在参数表、可脚本校验），不是建议。实例出处：XDanger S2 世界规格（2026-10 参考工程快照：`VOXEL_SIZE = 0.1`、格线容差 `0.0001`、玩家站高 `1.7 m` = 17 格）；规则本身不依赖该工程，换目标世界时按新世界的常量重填，不重写流程。

### 3.1.1 体素单位方块大小（唯一常量）

1. 目标世界的单位方块边长必须是**唯一命名常量**，全工程只允许一处定义；其余环节只消费，不得各自内嵌数值或各自四舍五入。
2. 世界坐标 ↔ 格坐标换算走统一入口（`WorldToGrid` / `GridToWorldMin`），使用**整数格 + 半开区间**；格线吸附用**单一量化容差**（0.1 这类值不能被二进制浮点精确表示，必须显式容差而非裸 `floor`）。
3. 边界外格坐标必须**显式失败**，不得静默夹回。
4. 换体素边长（如 0.125 m → 0.1 m）是**重采样**：按世界米坐标换算，保留源/目标边长、注册变换、占用差异与两侧哈希；禁止只改 metadata 里的一个数字。

### 3.1.2 人物对应体素大小（整数格高）

目标世界存在可行动角色（人物）时：

1. 角色**站立高度**必须对应**整数个**单位方块（例：站高 1.7 m ÷ 0.1 m = 17 格）；角色站高、蹲高、趴高、半径的排序约束在同一处声明并校验。
2. 供角色通行的净空、门洞、台阶单级高度必须按**同一单位方块**量化后再与角色姿态尺寸比对；禁止"门高按米、台阶按格、人物按 1.7 m 手估"多套口径并存。
3. 参数表必须登记：单位方块边长、角色站高与对应格数、格线容差；缺任一项，通行/净空/高程带类检查标 `UNVERIFIED`，不得判 PASS。

### 3.1.3 机器校验（仪器，非门禁）

实现：`scripts/unit_character_contract.py`（只读；exit 0 通过 / 1 未通过 / 2 用法）。四项读数：

- **C1 定义唯一**：扫描工程文件里 `voxelSize` 类赋值/键（含 `proxyVoxelSize` 等变体），定义文件必须全部落在 `allowed_definition_files` 白名单（未给白名单时最多 1 个文件），定义值必须等于契约方块边长（容差内）；0 命中 = 口径未登记，判 FAIL。
- **C2 站高整数格**：站立高度 ÷ 方块边长必须为整数（容差内）；蹲/趴高非整数记 WARN。
- **C3 姿态排序**：`0 < radius <= stand_radius`、`2*stand_radius <= height`、`2*radius <= prone <= crouch <= height`。
- **C4 净空量化**：契约 `clearances[]` 每个高度整除方块边长。

`--self-test` 带 6 个负样本回归（好契约 PASS；双定义位/竞争尺寸/站高非整数/姿态乱序/净空未量化各 FAIL）。它只产读数与结论、不停手；要升为可拦人门禁，须按 `04` §0 的两条前置条件在真实工程留负样本后登记。

## 4. 不可裁剪项（所有类型与尺度都必须检查）

| 项目 | 归属 |
|---|---|
| 注册同源性（投影/生成数据与参考同源） | 空间忠实度 |
| 占用重叠 | 体素工程质量 |
| 悬浮 / 下陷 / 越界 | 体素工程质量 |
| 接地或贴合（物体与基准面的接触关系） | 体素工程质量 |
| 根节点唯一性与构建幂等 | 体素工程质量 |
| 固定机位参数可复现 | 视觉/语义 |
| 动态体有可见渲染面 | 视觉/语义 + 玩法 |
| 破坏“三证合一”（仅在玩法含破坏时） | 玩法/物理 |
| 指标与证据可追溯（非空投影源、可解析 JSON） | 全部 |

## 5. 可裁剪项（按对象类型与尺度）

| 检查项 | 适用对象 | 可裁剪条件 |
|---|---|---|
| 路网连通性与可走性 | 城市、聚落、街区 | 对象不含道路系统时裁剪，但须保留“净空/通行”替代项 |
| POI 中心误差、地标足迹重叠率 | 城市、聚落 | 无 POI 体系时改用“关键构件尺寸链误差” |
| 岸线/水体重叠率 | 自然景观、港区类城市 | 无水系时裁剪 |
| 高程分层一致性 | 自然景观、城市（多台地） | 单层平坡对象可降为“基准面偏差” |
| 主路线可通行 | 城市、街区、室内 | 室内默认**保留“通行与净空”替代检查**；仅当项目明确无角色玩法时才可整体裁剪，并须登记“本轮不做玩法验收” |
| 碎块峰值与回收 | 含可破坏动态体 | 无破坏系统时裁剪 |
| 射线命中一致性 | 含交互 | 无交互时裁剪 |

裁剪写法固定为参数表一行：`裁剪项 | 理由 | 替代检查项 | 确认人`。缺任一段视为漏检。

## 6. 三个裁剪示例（看结构，不要抄数值）

**单体建筑（S3）**：G1 收集立面照与尺寸标注；G2 注册基准 = 包围盒 + 基准面 + 关键尺寸锚点，无路网与 POI；G3 先体量轮廓后主结构；G4 立面构件与屋顶；G5 重点查接地、悬挑是否悬浮、开洞是否越界；G6 机位用正立面/侧立面/四分之三视角；玩法类检查全部裁剪并登记。

**自然地形 + 水体（S4/S5）**：G1 以等高线/DEM 与水位数据为主，照片只用于质感；G2 做地理配准，注册基准 = 等高线 + 水位基准；G3 等高线放样得坡面；G4 水岸线与植被群；G5 重点查坡面连续性、水面与地形是否互相穿透、水岸线一致性；G6 机位含高空正交投影与贴近水面视角；裁剪 POI 与路网项。

**室内空间（S1/S2）**：G1 房型图 + 剖面 + 室内照；G2 注册基准 = 房间原点 + 层高 + 门洞位置；G3 地坪与墙体；G4 门洞、楼梯、陈设；G5 重点查净空（顶面到地面）、门洞通过性、家具是否与墙体穿插；G6 机位用室内人眼高度视角；裁剪路网、POI、岸线、碎块项，但保留“净空/通行”替代检查。

## 7. 与验收检查表的映射

图纸集骨架（与 `02` §2.1 对接；只给结构，具体图号与深度由项目参数表定）：

| 对象类型 | 必含图 | 可裁剪图 | 注册基准 |
|---|---|---|---|
| 城市/聚落 | 总平面、道路与轴线、关键地标 footprint、南北剖面、语义图 | 单栋立面、室内图 | POI + 路网 |
| 街区/场地 | 场地平面、主轴线、主要构筑物平面、剖面 | 单栋立面、铺装大样 | 场地边界 + 主轴线 |
| 单体建筑 | 平面、关键剖面、正/侧立面、屋顶平面 | 室内图、场地图 | 包围盒 + 基准面 + 尺寸锚点 |
| 室内 | 房型平面、剖切图、展开立面、净空图 | 场地图、总平面 | 房间原点 + 层高 + 门洞位置 |
| 自然景观 | 等高线/高程分带图、水系与岸线图、剖面 | 单株/单石大样 | 地理配准后的等高线与水位基准 |
| 大型道具/载具 | 主轴线图、三视轮廓、部件尺寸链表 | 场地图 | 主轴线 + 关键部件尺寸链 |
| 混合场景 | 各子对象的必含图 + 共用总平面与注册对照图 | 按子对象裁剪 | 全场景共用一套注册，按子对象登记 |

`references/04-verification.md` 的四张表按下列方式取用：

| 表 | 城市/聚落 | 街区/场地 | 单体建筑 | 室内 | 自然景观 | 道具/载具 |
|---|---|---|---|---|---|---|
| 空间忠实度 | 全表 | 全表 | 轮廓与尺寸链为主 | 房间尺寸与层高为主 | 高程与岸线为主 | 轮廓与比例为主 |
| 体素工程质量 | 全表 | 全表 | 全表 | 全表 | 全表 | 全表 |
| 视觉/语义 | 全表 | 全表 | 剪影/立面/材质为主 | 净空比例与陈设覆盖 | 坡面/水岸/植被为主 | 剪影与部件拓扑为主 |
| 玩法/物理 | 全表 | 通行与净空为主 | 多为裁剪 | 通行与净空为主 | 多为裁剪 | 接地与重心为主 |

体素工程质量表与“指标可追溯”在任何类型下都不得裁剪。

## 8. 本文件的通用性边界

- 对象类型与尺度等级是**分派约定**，不是行业标准；团队可改名，但必须保留“类型决定证据、尺度决定预算”这两条语义。
- 表 3 的体素尺寸与表 5 的裁剪条件是经验量级，必须用项目实测替换；未实测的取值标 UNVERIFIED。
- 本文件不覆盖“复刻目标本身不明确”的情形：那属于 G0 问题，应先与用户对齐、而不是在这里选一个类型硬做。
