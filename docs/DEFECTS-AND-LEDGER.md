## 3 推进记录（按时间）

### 2026-10-14 · 缺陷① 增量 1（完成）

- 抽取登记外部件（P1，MIT，commit `11016c9a…`）120 文件 / 820,844 字节 → 隔离目录，带逐文件 SHA-256 与依赖探测（`missing=0`）；参考区原包未动。
- 新增适配器：把入包闸产物转成多视图求解输入；内置**角色白名单**（只收 `front/side/back/top`）。
- **尺度前置闸**：`--units m` 时每个入选角色必须有 `px_per_m` + 可追溯来源，缺任一项 → **REFUSED（退出码 3）且不跑 solver**。
- 自检 **6/6 PASS**（含负样本：尺度声明错 → 检出冲突；来源为空 → fail-closed）。
- 真实试跑暴露并修掉一个缺口：按面积挑视图会把 C 级图当尺子 → 改为 A>B>C>D 优先。

### 2026-10-14 · 缺陷① 增量 2（公共尺模式）

- 尺度溯源核查：目标工程的"18 m"自带 `self-defined (no measurable anchor)`；项目里的 px/m 均为**渲染相机**换算 → 参考图无可追溯 px/m。
- 新增 **公共尺模式**：同一实物在两张图各量一次像素，单位抵掉，比的是"Z 等于多少把尺"；尺必须声明 `unit_name` 且各视图一致，不一致即拒判；产物标 `verdict_scope=same-common-unit-ratio`。
- 自检扩到 **8/8 PASS**；真实跑（只 front+side）→ **REFUSED**（尺度不全，不生成判据）。

### 2026-10-14 · 缺陷① 增量 3（实测，REFUSED）

- 新增测量脚本：每图两次目标约束分割（船体 + 同型刚性件炮塔），从**掩膜像素**机器量 bbox，用无量纲比值做跨视图比较；带合理性检查（尺必在船框内、比值落 0.05–0.45）。
- 阻断点 1（正视）：炮塔分割塌陷（掩膜仅 7×7 px，比值越界）⇒ 拒判。
- 阻断点 2（侧视）：大炮塔被近景舰上层建筑遮挡，**归属未定** ⇒ 拒判（属缺陷②）。
- 另发现：两张船体掩膜**过分割**（把邻近舰船吃进来），故"船高"读数不可信。
- 结论：**挡住的不是测量工具，而是部件分离与身份认定**——登记为缺陷②的第一个实名案例。

### 2026-10-14 · ⑭ 引擎绑定（单帧 → 多机位）

- 新增件：数据层预览渲染器（等距/俯视/正视，确定性）与引擎预览驱动（占用 → 单 `.vox` → ASCII 工程 → 离线 UrhoXRuntime 截图）。
- 结果：街区 302,636 体素（含场外地坪）单帧；内厅揭顶版 24,480 体素单帧；多机位 5（街区）+ 3（内厅）。
- 四个引擎实测坑（已写进 `references/05 §7.1`）：① 离线 runtime **不执行脚本自定义 `Start()`**（顶层执行才生效）② `.vox` 调色板**差一格**（色号 1 → `RGBA[0]`）③ 导入前预填满槽位 ⇒ 纯黑 ④ 相机进体积内部不出画面（需 `*Inside` 变体或揭顶）。
- 口径：**单帧预览 ≠ 验收**；仍欠玩法/性能读数与光照保真。
