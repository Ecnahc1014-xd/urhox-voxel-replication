# 参考数据的解析与产出契约（图纸 / BIM / 实测 / 场地）

本文件回答：**拿到一份图纸、IFC、实测导出或场地底图之后，怎么把它变成能进主数据的机器可读表**，
以及**哪些解析结果可以当证据、哪些只能当线索**。

分工（不重复正文）：

- `09` / `09a` / `11`：**去哪拿**这些文件（通道、站点、限流、零结果登记）。
- `01`：拿到之后**怎么分级**（A/B/C/D、追溯链、冲突）。
- `02`：注册链与往返检查（**输入侧自己的制图**）。
- **本文件：外部数据 → 结构化表的解析口径与产出契约。** 它不新增门禁。

## 0 四条纪律

1. **先判"矢量还是位图"，再谈精度。** 两者的精度上限差一个量级，混为一谈会让整轮结论失真。
2. **解析结果是"图纸声称的尺寸"，不是现场实测。** 与 `02` 的往返检查衔接，差异必须登记而不是取其一。
3. **任何解析产物必须可追溯**：源文件哈希 + 解析器与版本 + 参数 + 单位，四者缺一即不得进主数据。
4. **数量不是形状。** 构件数量/工程量是计量口径，**不得**当几何证据（形状只能来自几何源）。

## 1 第一步：判定输入形态（决定精度上限）

| 形态 | 怎么判 | 精度上限 | 允许的结论 |
|---|---|---|---|
| **矢量 CAD**（DXF/DWG/DGN） | DXF 能读到实体表（线/弧/圆/多段线/图层/尺寸标注） | **高**（几何直接可算） | 轮廓、尺寸链、图层语义；仍须第二源交叉 |
| **矢量 PDF**（施工图/电气原理图） | 能取到文字层与路径（`fitz`/`pdfplumber` 拿到 `char`/`line`） | **高**：基于矢量几何提取，**无 OCR 误差** | 元件清单（位号/型号/数量）、导线与端子拓扑、标题栏 |
| **位图 / 扫描件** | 只有像素；PDF 无文字层 | **低**：必须 OCR/视觉推断 | 只能作线索与补全；**每项必须带置信度**，低置信项逐个标记，不得当 A 级 |
| **BIM / IFC / Revit** | 有构件树与属性 | **高**（属性与数量是权威） | 构件属性、数量（面积/体积/长度）、分组与关系 |
| **实测导出**（激光测距类） | 有距离/倾角/坐标/精度列 | **高**（但要问精度列） | 轮廓与显式尺寸；近矩形房间**方正化**、直角化 |
| **场地底图**（OSM 类） | 有路网/建筑足迹经纬度 | 中（平面可靠、高度不可靠） | 平面足迹、路网、方位；**俯视原理上给不出层数** |

**判定方法（可复算）**：对 PDF，先试取文字层与矢量路径；两者都拿不到才降级为位图路线，
并在解析产物里写明"输入形态 = 位图 / OCR"。**这条判定本身要留证**（一行命令 + 一行结果）。

## 2 各形态能取到的字段（解析目标清单）

| 形态 | 目标字段 |
|---|---|
| DXF/DWG | 实体几何（几何类型 + 坐标）、图层名、块引用、尺寸标注（值 + 位置）、标题栏文本（图号/图名/比例/材料/设计/校对/审核） |
| 矢量 PDF（施工图） | 文字块与位置、材料表行、尺寸标注（含 Ø/R/±/角度/配合）、图框字段 |
| 矢量 PDF（电气） | 元件清单（位号/型号/数量）、导线连接拓扑（串并联、流向）、端子表、标题栏 |
| 位图 / 扫描件 | OCR 文本块 + **置信度** + 图像坐标；表格需单独重建并标注"重建" |
| BIM / IFC | 构件类型与 ID、属性集、数量（计数/面积/体积/长度）、层级与分组、坐标系与高程基准 |
| 实测导出 | 距离、倾角、水平/垂直角、X/Y/Z、精度；**逐行保留原始列名**（列名的含义必须写明，不得猜） |
| 场地底图 | 路网（线）、建筑足迹（多边形）、命名与类型标签、坐标系 |

## 3 产出契约（**唯一格式**）

每份解析产物必须随附一张表头（可放在 JSON 顶部或同目录 `.meta.json`）：

```json
{
  "schema": "urhox-parsed-source/1",
  "sourceFile": "<相对路径>",
  "sourceSha256": "<源的 sha256>",
  "sourceForm": "vector-cad | vector-pdf | raster-ocr | bim-ifc | survey-export | site-base",
  "parser": {"name": "...", "version": "...", "deps": ["ezdxf 1.4.4", "..."]},
  "params": {"...": "本次解析用到的全部参数"},
  "units": {"length": "mm|m", "angle": "deg"},
  "coordinateFrame": {"up": "y|z", "originNote": "..."},
  "lowConfidence": ["<被标记为低置信的条目引用>"],
  "extractedAt": "<date>"
}
```

**硬要求**：

1. 源文件哈希与实际解析的字节必须对应（改过源就要重算，不允许"哈希是旧的、数据是新的"）。
2. 每个数值条目带**单位**与**来源位置**（图层/页码/行号/构件 ID），否则事后无法复核。
3. `lowConfidence` 非空时，该产物整体**降级**（见 §4）。
4. 解析器版本必须写死到具体版本号；只写库名不算（不同版本 Otsu/解析行为会变）。

## 4 精度与合法性（怎么用这些数）

- **图声称值 vs 实测量值 vs 官方数据**三者不一致时，登记为**冲突**（照 `01` 的冲突表），不得静默取其一。
- **位图/OCR 路线**：任何尺寸不得进入 A 级；用于"补全线索"与"交叉提示"，
  且必须在证据里标"位图解析 + 置信度 x.xx"。
- **矢量路线**：可作较高等级输入，但仍需与**另一独立来源**（官方数据 / 实测 / 第二格式）交叉；
  单来源的矢量解析结论按 `01` 降级处理。
- **BIM 数量**：可作计量口径（与 `21` §6 的真实体积算法对照），**不得**当形状依据。
- **场地底图**：平面足迹可用；高度/层数一律不可用（俯视原理限制）。

## 5 依赖与环境

| 用途 | 依赖 | 备注 |
|---|---|---|
| DXF 读取/写出 | `ezdxf` | **DXF 可直读**；DWG 需先转换（多数库不自带 DWG 解码） |
| 矢量 PDF | `fitz`(PyMuPDF) / `pdfplumber` | 先试文字层与矢量路径 |
| OCR（扫描件） | Tesseract 一类 | 结果**必带置信度**；表格需重建 |
| BIM / IFC | IFC 解析器 / 转换器链 | 注意**坐标系与高程基准**（IFC 的 Z 常为高程，与游戏 Y-up 不同） |
| 场地底图 | `osmnx` + `geopandas`（+ `ezdxf` 导出 DXF） | 拉取路网/足迹 → SVG/GeoPackage/DXF |
| 3D 网格 | `trimesh` / `cadquery` | 注意单位与轴向 |

**只读纪律（采纳）**：外部件自带的一个好习惯——**不自动装包**；
缺依赖时**明确报错并给出安装命令**，需要装包时必须显式确认参数（如 `--confirm`）。
本工程的解释器绑定与依赖判据见 `20` §1/§3。

## 6 许可边界

- 标 `Proprietary` 或**未声明许可**的解析件（如某些"专业版图纸解析"）：
  **只读方法、重写实现**，不得搬代码，不得随交付物分发（细目见 `18` §7 与 `assets/external-skills-index.json`）。
- 第三方 OCR / 转换器链的许可单独核；不得假定与主件同许可。

## 7 已知边界

1. 本文件不规定**用什么工具**（那是 `18`/`assets` 的采纳决策），只说**产出必须长什么样**。
2. 各库的版本行为差异未被穷举；换版本后**必须重跑并更新 `parser.version`**。
3. 未在本工程对 OCR 路线的置信度阈值做过标定；引用置信度只能作相对比较。
